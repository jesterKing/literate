Browser Mermaid preview

A diagram can explain structure at a glance, but only if the reader can see it while reading the explanation. Literate therefore turns an ordinary Mermaid code fence into a diagram inside VS Code's Markdown preview. The Markdown source stays visible and editable in the document; the preview supplies the visual companion.

flowchart TD
    Source[Mermaid fence in the book] --> Container[Safe preview container]
    Container --> Renderer[Locally bundled Mermaid renderer]
    Renderer --> Diagram[SVG shown beside the source]

No renderer is fetched from the internet and no other extension is trusted to provide one. Literate bundles Mermaid itself, which makes the preview reproducible and prevents a document from silently selecting a different runtime. VS Code supplies the Electron and Chromium baseline needed to run that local renderer.

This chapter concerns the immediate browser preview only. Static SVG files for publication travel through a separate, explicitly asynchronous adapter. The pure generation engine does not open a browser, and reading or generating a project must not acquire that side effect accidentally.

The preview program is ordinary browser JavaScript bundled locally as an IIFE. Keeping it outside the extension's TypeScript compilation avoids introducing DOM and Mermaid dependency types into the Node extension. Its readable source remains a generated program file; the minified browser bundle is a later build artifact. The mechanical root that assembles this file is collected in the program assembly appendix.

A weak map ties retained source to the actual container, not its source line or text. Replacing a Markdown preview therefore creates fresh work even for an identical diagram. IDs use monotonic container and attempt numbers and avoid existing DOM IDs, including IDs from other preview plugins.

<<Mermaid preview state>>=
const selector = 'pre.literate-mermaid';
const states = new WeakMap();
let nextContainer = 0;
let pending = false;
let running = false;

Each render attempt gets a fresh diagram ID. Check both the SVG ID and Mermaid's temporary wrapper ID before using it.

<<Mermaid preview state>>=+
function diagramId(state) {
    let id;
    do {
        id = `literate-mermaid-${state.container}-${++state.attempt}`;
    } while (document.getElementById(id) || document.getElementById(`d${id}`));
    return id;
}

Security and resource limits are fixed by the client. No icons, external fonts, assets or event bindings are registered. Strict Mermaid SVG is the only HTML inserted. Disallowing all directives and YAML frontmatter is intentionally more conservative than relying on Mermaid's list of protected configuration keys: per-diagram settings must not enable loose rendering or disable limits. This also means otherwise harmless title/config frontmatter is unsupported. Initialize once immediately, even before DOM readiness or with no diagrams, to disable Mermaid's automatic generic .mermaid scan. Subsequent initialization is confined to the serial render queue.

<<Mermaid preview configuration>>=
function theme() {
    const wrapper = document.querySelector('.literate-document');
    return getTheme(wrapper?.getAttribute('data-literate-theme'))?.name || defaultThemeName;
}

function applyTheme() {
    let sheet = document.getElementById('literate-theme-style');
    if (!sheet) {
        sheet = document.createElement('style');
        sheet.id = 'literate-theme-style';
        document.head.appendChild(sheet);
    }
    const css = themeCss(getTheme(theme()));
    if (sheet.textContent !== css) { sheet.textContent = css; }
}

The wrapper's catalogue name selects both the scoped document stylesheet and Mermaid palette, independently of VS Code's theme. Missing or invalid names use Rose Pine Dawn. Only trusted catalogue CSS is installed, with no body styling; the single stylesheet is applied even when the document contains no diagrams.

Only the selected theme varies between configurations. Security settings, resource limits and local font defaults remain fixed for every render.

<<Mermaid preview configuration>>=+
function configuration(currentTheme) {
    return {
        startOnLoad: false,
        securityLevel: 'strict',
        suppressErrorRendering: true,
        maxTextSize: 50000,
        maxEdges: 500,
        ...mermaidTheme(getTheme(currentTheme)),
        fontFamily: 'sans-serif',
        htmlLabels: false,
        flowchart: { htmlLabels: false },
        secure: ['secure', 'securityLevel', 'startOnLoad', 'suppressErrorRendering',
            'maxTextSize', 'maxEdges', 'theme', 'themeVariables', 'fontFamily', 'htmlLabels', 'flowchart']
    };
}

mermaid.initialize(configuration(defaultThemeName));

Reject oversized source and diagram-level configuration before invoking Mermaid, rather than allowing a diagram to alter the preview policy.

<<Mermaid preview configuration>>=+
function validateSource(source) {
    if (source.length > 50000) { throw new Error('Diagram exceeds the 50000 character limit.'); }
    if (/%%\s*\{/.test(source) || /^\s*---(?:\s|$)/.test(source)) {
        throw new Error('Mermaid directives and frontmatter are disabled in this preview.');
    }
}

The last installed markup distinguishes our own SVG/error text from an in-place Markdown source update. Original source never comes from rendered SVG. Failed attempts are cached too, so repeated update events do not continually retry a syntax error; changing source or theme permits recovery. Classes and source-line attributes remain on the original pre element.

<<Mermaid preview source tracking>>=
function stateFor(element) {
    let state = states.get(element);
    if (!state) {
        state = { container: ++nextContainer, attempt: 0 };
        states.set(element, state);
    }
    if (state.markup !== element.innerHTML) {
        state.source = element.textContent || '';
        state.markup = element.innerHTML;
        state.completedTheme = undefined;
    }
    return state;
}

After an asynchronous render, verify that the container, its contents and the current theme still match the work that was started.

<<Mermaid preview source tracking>>=+
function isCurrent(element, state, markup, currentTheme) {
    return element.isConnected && element.matches(selector)
        && element.innerHTML === markup && state.markup === markup
        && theme() === currentTheme;
}

Report failures through textContent, including the original source for inspection. An alert role and accessible label identify the rendering error without treating either the error message or source as HTML.

<<Mermaid preview source tracking>>=+
function showError(element, source, error) {
    const message = error instanceof Error ? error.message : String(error);
    element.textContent = `Mermaid diagram could not be rendered: ${message}\n\n${source}`;
    element.setAttribute('role', 'alert');
    element.setAttribute('aria-label', 'Mermaid diagram rendering error');
}

Every initialize/render pair runs to completion before the next initialization. Theme or content events during an await request another pass. A stale result is never installed into a detached, edited or differently themed container. We do not invoke bindFunctions: interactive callbacks are unnecessary for this strict preview. Mermaid performs its own temporary-render DOM cleanup.

<<Mermaid preview rendering>>=
async function renderElement(element, currentTheme) {
    const state = stateFor(element);
    if (state.completedTheme === currentTheme) { return; }
    const markup = element.innerHTML;
    let result;
    let failure;
    try {
        validateSource(state.source);
        mermaid.initialize(configuration(currentTheme));
        result = await mermaid.render(diagramId(state), state.source);
    } catch (error) {
        failure = error;
    }
    if (!isCurrent(element, state, markup, currentTheme)) { return; }
    if (result) {
        element.innerHTML = result.svg;
        element.removeAttribute('role');
        element.removeAttribute('aria-label');
    } else {
        showError(element, state.source, failure);
    }
    state.markup = element.innerHTML;
    state.completedTheme = currentTheme;
}

The queue coalesces bursts without losing updates, including those delivered while Mermaid is awaiting layout. The theme is sampled before each diagram, not once for the whole document. The configuration key is the resolved catalogue name, so even two palettes with the same light/dark mode trigger a fresh render.

<<Mermaid preview scheduling>>=
async function drain() {
    running = true;
    try {
        while (pending) {
            pending = false;
            for (const element of document.querySelectorAll(selector)) {
                if (element.isConnected) { await renderElement(element, theme()); }
            }
        }
    } finally {
        running = false;
    }
}

Every update requests a pass, but only an idle queue starts a new drain. Events arriving during a render are handled by the existing drain's next iteration.

<<Mermaid preview scheduling>>=+
function schedule() {
    applyTheme();
    pending = true;
    if (!running) { void drain(); }
}

VS Code dispatches its content-update event on window, including replacement documents. Observe theme attributes in the body subtree, not body classes or Mermaid's own SVG writes. Waiting for DOMContentLoaded also supports scripts loaded before the body exists.

<<Mermaid preview startup>>=
function start() {
    const observer = new MutationObserver(schedule);
    observer.observe(document.body, {
        attributes: true, subtree: true, attributeFilter: ['data-literate-theme']
    });
    window.addEventListener('vscode.markdown.updateContent', schedule);
    schedule();
}

if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', start, { once: true });
} else {
    start();
}
