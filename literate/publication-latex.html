An in-memory LaTeX book

This chapter owns src/publication-latex.ts. It consumes the controlled Pandoc bridge, not a second Markdown parser. Root SETTINGS use the shared resolver; no files, processes, browser APIs, or publishing commands are involved. The injected converter is trusted: it must convert JSON to a LaTeX body, preserve raw LaTeX, use top-level chapters, and disable Pandoc syntax highlighting (--no-highlight, tested on Pandoc 3.7.0.2). The options passed to it make that contract explicit; they are not CLI arguments.

Only catalogue palettes are accepted, with no print remapping. Each side falls back to marginMm, then 20 mm. All supplied margins must be finite in [5, 50], leaving at least 80 mm width and 100 mm height after subtracting opposite sides. Family names deliberately exclude fontspec options, paths, and TeX metacharacters.

Root settings resolve first, including note inheritance from the root body. Per-role programmatic overrides apply next: bodyFont does not retroactively change the resolved note family; use noteFont to override that role. This avoids mistaking an explicit root note equal to its body for an inherited value. Invalid root settings remain errors even when an option overrides that role.

function fontName(value: string): string {
    if (typeof value !== 'string' || !/^[A-Za-z0-9][A-Za-z0-9 .-]{0,99}$/.test(value)) {
        throw new Error('Font must be a simple family name (1–100 ASCII characters)');
    }
    return value;
}
function checkOptions(options: LatexOptions, settings: PublicationSettingsResult): CheckedOptions {
    const theme = getTheme(options.theme ?? defaultThemeName);
    if (!theme) { throw new Error('Unknown publication theme'); }
    const papers = new Map<string, [string, number, number]>([
        ['A4', ['a4paper', 210, 297]], ['A5', ['a5paper', 148, 210]],
        ['letter', ['letterpaper', 215.9, 279.4]], ['legal', ['legalpaper', 215.9, 355.6]]
    ]);
    const paper = papers.get(options.paper ?? 'A4');
    const margin = options.marginMm ?? 20;
    const overrides = [options.marginTopMm, options.marginRightMm,
        options.marginBottomMm, options.marginLeftMm];
    const [top, right, bottom, left] = overrides.map(value => value ?? margin);
    if (!paper || [margin, top, right, bottom, left].some(value =>
        !Number.isFinite(value) || value < 5 || value > 50) ||
        paper[1] - left - right < 80 || paper[2] - top - bottom < 100) {
        throw new Error('Invalid paper or margin; require 5–50 mm and an 80 × 100 mm body');
    }
    const geometry = overrides.some(value => value !== undefined)
        ? `top=${top}mm,right=${right}mm,bottom=${bottom}mm,left=${left}mm`
        : `margin=${margin}mm`;

The boolean policy is checked at runtime too; callers need not be TypeScript. Defaults come only from the shared settings resolver, not a second catalogue.

Data is never interpolated as commands. Destination identifiers are encoded again in a private namespace so even a manually constructed snapshot cannot inject TeX. Name wrapping inserts discretionary breaks, not per-character font groups. We cap names at 512 Unicode code points; larger names fail explicitly, never abbreviate. Control characters are rejected rather than interpreted by TeX.

<<publication LaTeX encoding>>= 
function checkText(text: string): void {
    if (/[\u0000-\u0008\u000b-\u001f\u007f]/u.test(text)) {
        throw new Error('Unsupported control character in publication text');
    }
}
function tex(text: string): string {
    checkText(text);
    const escapes = new Map([
        ['\\', '\\textbackslash{}'], ['{', '\\{'], ['}', '\\}'], ['#', '\\#'],
        ['$', '\\$'], ['%', '\\%'], ['&', '\\&'], ['_', '\\_'],
        ['^', '\\textasciicircum{}'], ['~', '\\textasciitilde{}']
    ]);
    return text.replace(/[\\{}#$%&_^~]/g, character => escapes.get(character)!);
}
function target(value: string): string {
    let result = 'lit-';
    for (let index = 0; index < value.length; index++) {
        result += value.charCodeAt(index).toString(16).padStart(4, '0');
    }
    return result;
}

function nameText(name: string): string {
    if (Array.from(name).length > 512 || /[\r\n\t]/.test(name)) {
        throw new Error('Fragment names must be single-line and at most 512 code points');
    }
    return Array.from(name, character => tex(character)).join('\\allowbreak{}');
}

Colours are validated even though the catalogue and style adapter are trusted. The code font retains common/contextual ligatures by default; disabling them adds RawFeature={-calt} for D2's contextual substitutions. D2Coding has no italic face: fontspec explicitly synthesizes slanted regular and bold faces with FakeSlant. The same policy applies to an overridden code family; no implicit italic lookup.

function pageLink(id: string, label: string): string {
    const destination = target(id);

The book is borderless and the entire page uses the selected background. Ordinary code uses the renderer's escaped Verbatim blocks. The verbatim and Highlighting environments remain compatibility aliases, not support for Skylighting token commands. Strikeout and tight lists are supported. The converter must not emit a standalone preamble or highlighted prose code. LuaLaTeX is the intended compiler, with installed fonts and packages.

FancyVerbBreakStart/Stop lets fvextra inspect the contents of a styled run. Styles group runs rather than glyphs. This retains shaping within a run; a style boundary can still split a ligature. PDF copying is not a source-code transport. The renderer harness validates styled-run wrapping and contextual glyph substitution on three A5 palettes. Only the three command characters need escaping inside Verbatim. Other TeX metacharacters keep verbatim catcodes. Escaping the backslash also prevents a literal end-environment string from ending the environment. Each style run is split at physical newlines so no macro argument crosses a Verbatim line.

function verbatimText(text: string): string {
    checkText(text);
    return text.replace(/[\\{}]/g, character => {
        if (character === '\\') { return '\\textbackslash{}'; }
        return character === '{' ? '\\textbraceleft{}' : '\\textbraceright{}';
    });
}
function styled(text: string, scope: string, theme: LiterateTheme): string {
    const style = syntaxStyle(scope, theme);
    return text.split('\n').map(line => line.length ?
        `\\LitStyle{${color(style.color)}}{${style.bold ? '\\bfseries' : ''}}` +
        `{${style.italic ? '\\itshape' : ''}}{${verbatimText(line)}}` : '').join('\n');
}

Literal slices retain whitespace and intersect full-context style ranges.

<<publication LaTeX code>>=+ 
function literal(data: Highlighted, start: number, end: number, theme: LiterateTheme): string {
    if (start === end) { return ''; }
    let cursor = start;
    let result = '';
    for (const span of data.spans) {
        const left = Math.max(start, span.start), right = Math.min(end, span.end);
        if (left >= right) { continue; }
        result += verbatimText(data.text.slice(cursor, left));
        result += styled(data.text.slice(left, right), span.scope, theme);
        cursor = right;
    }
    result += verbatimText(data.text.slice(cursor, end));
    return '\\begin{Verbatim}[commandchars=\\\\\\{\\}]\n' + result +
        (result.endsWith('\n') ? '' : '\n') + '\\end{Verbatim}\n';
}

The adapter must return ordered, disjoint ranges within the UTF-16 string. Reject bad ranges rather than silently dropping or repeating source. References take precedence over syntax styles and preserve the order of all surrounding literals. Every reference gets a display-only line break and a modest hanging indent. Its macro is argument-free, defined outside Verbatim, and invoked outside it as well. The unboxed paragraph can break across pages, unlike the probe's parbox.

<<publication LaTeX code>>=+ 
function validateHighlight(data: Highlighted): void {
    checkText(data.text);
    for (const ranges of [data.spans, data.references]) {
        let end = 0;
        for (const range of ranges) {
            if (!Number.isInteger(range.start) || !Number.isInteger(range.end) ||
                range.start < end || range.end <= range.start || range.end > data.text.length) {
                throw new Error('Invalid highlighting ranges');
            }
            end = range.end;
        }
    }
}
function macroName(index: number): string {
    let suffix = '';
    do { suffix = String.fromCharCode(65 + index % 26) + suffix;
        index = Math.floor(index / 26) - 1;
    } while (index >= 0);
    return `LitReference${suffix}`;
}

Adjacent spans with identical visual styles must form one run even if highlight.js split them into different unstyled nodes. This keeps operator shaping independent of emitter tree boundaries.

<<publication LaTeX code>>=+ 
function mergeStyles(data: Highlighted, theme: LiterateTheme): void {
    const merged: Highlighted['spans'] = [];
    let previousStyle = '';
    for (const span of data.spans) {
        const style = JSON.stringify(syntaxStyle(span.scope, theme));
        const previous = merged[merged.length - 1];
        if (previous && previous.end === span.start && style === previousStyle) {
            previous.end = span.end;
        } else { merged.push({ ...span }); }
        previousStyle = style;
    }
    data.spans = merged;
}

Family destinations live on base definitions; each contribution also has its own label. Previous/next links point at contribution pages, not merely the family. The heading requests room for its start and code, but no entire code block is boxed.

<<publication LaTeX contributions>>= 
function contribution(part: PublicationContribution, project: ParsedProject,
    theme: LiterateTheme, definitions: string[]): PandocBlock[] {
    const family = project.publication.fragments.find(item => item.target === part.fragmentTarget);
    if (!family) { throw new Error('Contribution has no fragment family'); }
    const position = family.contributions.indexOf(part.target);
    if (position < 0) { throw new Error('Contribution is absent from its family'); }
    const data = highlightContribution(part);
    validateHighlight(data);
    mergeStyles(data, theme);
    let output = '\\par\\Needspace{5\\baselineskip}\n' + anchor(part.target);
    if (part.kind === 'definition') { output += anchor(family.target); }
    output += `{\\fragmentfont\\raggedright\\color{publicationAccent} ${nameText(family.name)}` +
        `\\enspace\\ensuremath{${part.kind === 'definition' ? '\\equiv' : '+\\equiv'}}\\par}\n`;
    const navigation: string[] = [];
    if (position > 0) { navigation.push(pageLink(family.contributions[position - 1], 'Previous ')); }
    if (part.kind === 'append') { navigation.push(pageLink(family.target, 'Base ')); }
    if (position + 1 < family.contributions.length) {
        navigation.push(pageLink(family.contributions[position + 1], 'Next '));
    }
    if (navigation.length) { output += `{\\notefont\\small ${navigation.join('\\quad ')}\\par}\n`; }
    output += contributionBody(data, project, theme, definitions);
    return [{ t: 'RawBlock', c: ['latex', output] }];
}

Reference names remain complete, with superscript family-definition pages. The highlighter cannot invent a destination: returned names/targets are checked against the publication families. The existing bridge independently validates source references, missing targets, modifiers, and cycles before calling this renderer.

<<publication LaTeX contributions>>=+ 
function contributionBody(data: Highlighted, project: ParsedProject,
    theme: LiterateTheme, definitions: string[]): string {
    let cursor = 0, output = '';
    for (const reference of data.references) {
        if (!project.publication.fragments.some(family =>
            family.target === reference.target && family.name === reference.name)) {
            throw new Error('Unknown highlighted reference destination');
        }
        output += literal(data, cursor, referencePrefixEnd(data.text, cursor, reference.start), theme);
        const command = macroName(definitions.length);
        const label = '\\textless{}\\textless{}' + nameText(reference.name) +
            '\\textgreater{}\\textgreater{}';
        definitions.push(`\\newcommand{\\${command}}{\\par\\begingroup` +
            '\\leftskip=1.5em\\rightskip=0pt plus 1fil\\parindent=0pt' +
            '\\fragmentfont\\small\\noindent ' + pageLink(reference.target, label) +
            '\\par\\endgroup}');
        output += `\\${command}{}\n`;
        cursor = reference.end + (data.text[reference.end] === '\n' ? 1 : 0);
    }
    return output + literal(data, cursor, data.text.length, theme);
}

The reference paragraph supplies its own terminating line break. Consume exactly one immediately following newline, leaving any authored blank lines intact. On a standalone reference line, discard only its indentation, not earlier blank lines; the reference still uses the common 1.5em hanging display indent.

<<publication LaTeX contributions>>=+ 
function referencePrefixEnd(text: string, cursor: number, start: number): number {
    const lineStart = text.lastIndexOf('\n', start - 1) + 1;
    return /^[ \t]*$/.test(text.slice(lineStart, start)) ? Math.max(cursor, lineStart) : start;
}

Ordinary fenced and indented code is literal data, never fragment syntax. Render it ourselves before conversion: even with highlighting disabled, Pandoc switches to unsupported highlighting macros when code contains a verbatim terminator. The walker replaces only CodeBlock leaves, retaining prose, inline code and their containers. No opener unescaping or semantic reference/highlight adapter runs here.

<<publication LaTeX code>>=+ 
function ordinaryCode(blocks: PandocBlock[], theme: LiterateTheme): PandocBlock[] {
    return blocks.map(block => {
        switch (block.t) {
            case 'CodeBlock': {
                const text = block.c[1];
                const data: Highlighted = { text, references: [],
                    spans: text ? [{ start: 0, end: text.length, scope: '' }] : [] };
                return { t: 'RawBlock', c: ['latex', literal(data, 0, text.length, theme)] };
            }
            case 'Div': return { ...block, c: [block.c[0], ordinaryCode(block.c[1], theme)] };
            case 'BlockQuote': return { ...block, c: ordinaryCode(block.c, theme) };
            case 'BulletList': return { ...block, c: block.c.map(item => ordinaryCode(item, theme)) };
            case 'OrderedList': return { ...block,
                c: [block.c[0], block.c[1].map(item => ordinaryCode(item, theme))] };
            default: return block;
        }
    });
}

Only a successful bridge result reaches the injected converter. Converter rejection, invalid output, or template failure produces a diagnostic and no latex property. The first document provides a stable location for non-source-specific failures.

<<publication LaTeX render>>= 
export async function renderLatex(parsed: ParsedProject, options: LatexOptions,
    convert: LatexConverter): Promise<LatexResult> {
    let stage = 'latex-options';
    try {
        const settings = resolvePublicationSettings(parsed);
        if (settings.diagnostics.length) {
            return { diagnostics: [...parsed.diagnostics, ...settings.diagnostics] };
        }
        const checked = checkOptions(options, settings);
        const definitions: string[] = [];
        stage = 'latex-preparation';
        const prepared = preparePandoc(parsed, part =>
            contribution(part, parsed, checked.theme, definitions));
        if (!prepared.document) { return { diagnostics: prepared.diagnostics }; }
        prepared.document.blocks = ordinaryCode(prepared.document.blocks, checked.theme);
        stage = 'latex-conversion';
        const body = await convert(prepared.document, {
            standalone: false, syntaxHighlighting: 'none', topLevelDivision: 'chapter'
        });
        if (typeof body !== 'string') { throw new Error('Converter must return a LaTeX body string'); }
        stage = 'latex-template';
        return { latex: template(body, checked, definitions), diagnostics: [] };
    } catch (error) {
        return { diagnostics: [{ path: parsed.documents[0]?.path ?? '', line: 0, column: 0,
            code: stage, message: error instanceof Error ? error.message : String(error) }] };
    }
}

Deliberate boundaries

Images, raw author markup, tables, Mermaid, and unsupported links still fail in preparePandoc; this is not yet a whole-project book exporter. No assets are copied, fonts downloaded, or TeX files compiled. The caller must install Latin Modern, Monofur Nerd Font and D2CodingLigature Nerd Font Propo (or supply safe family overrides), and the listed TeX packages. Missing glyphs remain compiler errors/warnings to check, not a claim of universal Unicode coverage.

Prose and inline-code escaping remain the trusted Pandoc writer's responsibility; ordinary block code is escaped by this renderer before conversion. Converters must preserve trusted RawBlocks, without filters, external includes, or highlighting. The ignored out/publication-renderer harness compiles rosepine-dawn, hermonica and flexoki-light A5 fixtures, including nested containers, full references and long styled tokens. It retains logs, glyph traces, link/bounds checks and previews. Headless tests cover every catalogue theme, but all palettes, fonts, arbitrary container depths and pagination are not PDF-validated. References introduce display-only line breaks; executable copying must use original or tangled source. CLI adapters, heading identity, packaging, transactions and generation belong to their separate integration slices.
