Publication syntax without losing context

This chapter owns src/publication-highlight.ts and its headless tests. It does not expand fragments: semantic references remain authored display text, with a separate overlay for the LaTeX renderer. All offsets are half-open UTF-16 ranges in the displayed text, not source coordinates or Unicode code-point counts.

Display first, syntax second

Only literal segments decode escaped openers. Reference text remains unchanged, including authored whitespace in the name. Accumulating display lengths maps references after unescaping without rescanning them into accidental references. The bridge normally rejects missing targets and modifiers; this API also rejects them when called independently. Invalid segment reconstruction fails closed.

Raw offsets are checked before display lengths are substituted. A reference with an empty resolved target is just as unusable as an explicitly missing one.

<<publication highlighting display>>=
function displayContribution(part: PublicationContribution, screen: boolean): HighlightedContribution {
    const chunks: string[] = [];
    const references: HighlightedContribution['references'] = [];
    let rawOffset = 0, offset = 0;
    for (const segment of part.segments) {
        let text = segment.text;
        if (segment.kind === 'text') {
            text = text.replace(/\\\x3c\x3c/g, () => '<' + '<');
        } else {
            if (!screen && segment.modifier !== undefined) {
                throw new Error('Publication reference modifier is unsupported: ' + segment.name);
            }
            if (!screen && (segment.resolution.kind !== 'resolved' || !segment.resolution.target)) {
                throw new Error('Publication reference target is missing: ' + segment.name);
            }
            if (!segment.occurrenceTarget) {
                throw new Error('Publication reference occurrence target is missing: ' + segment.name);
            }
            if (segment.placement !== 'standalone' && segment.placement !== 'inline') {
                throw new Error('Publication reference placement is invalid: ' + segment.name);
            }
            if (segment.start !== rawOffset || segment.end + (segment.modifier?.length || 0) !== rawOffset + text.length) {
                throw new Error('Publication reference offsets do not match segment text');

A guarded private adapter

out/publication-probe/highlighting/context-probe.cjs and its README demonstrate that splitting around references loses multiline comment and template context. We highlight the displayed block once. We never parse highlighted HTML or CSS. The installed highlight.js is 11.9.0; its private _emitter.rootNode contract is version-gated, shape-checked, and checked for exact reconstruction. Upgrades must explicitly revisit this adapter and its regression tests, not silently fall back.

<<publication highlighting emitter>>=
function record(value: unknown): value is Record<string, unknown> {
    return typeof value === 'object' && value !== null;
}
function emitterRoot(text: string, language: string): unknown {
    if (hljs.versionString !== '11.9.0') {
        throw new Error('Publication highlighting requires highlight.js 11.9.0');
    }
    const result: unknown = hljs.highlight(text, { language, ignoreIllegals: true });
    if (!record(result) || !record(result._emitter) ||
        !record(result._emitter.rootNode)) {
        throw new Error('Unsupported highlight.js emitter shape');
    }
    return result._emitter.rootNode;
}

The traversal uses an explicit stack, not recursive JavaScript calls. Unscoped nodes inherit the nearest token scope. Embedded language:* wrappers are not semantic token scopes, so they do not overwrite that inheritance. A real nested scope does overwrite it, including subst (plain text) and unknown scopes (the CSS text reset). Dotted scope names are retained for consumers; styles use their primary class. Empty text creates no zero-width span.

<<publication highlighting traversal>>=
function syntaxSpans(text: string, root: unknown): SyntaxSpan[] {
    const spans: SyntaxSpan[] = [];
    const chunks: string[] = [];
    const stack = [{ node: root, scope: '' }];
    const seen = new Set<object>();
    let offset = 0;
    while (stack.length) {
        const { node, scope } = stack.pop()!;
        if (typeof node === 'string') {
            if (node.length) {
                spans.push({ start: offset, end: offset + node.length, scope });
                chunks.push(node);
                offset += node.length;
            }
            continue;
        }

Unknown or empty language names explicitly mean plain text. There is no automatic language detection, and semantic references still work in plain blocks. Syntax spans cover the entire nonempty display, including reference characters; the renderer intersects these ranges and gives semantic references precedence.

<<publication highlighting entry>>=
export function highlightContribution(part: PublicationContribution, screen = false): HighlightedContribution {
    const display = displayContribution(part, screen);
    display.spans = part.language && hljs.getLanguage(part.language)
        ? syntaxSpans(display.text, emitterRoot(display.text, part.language))
        : display.text.length ? [{ start: 0, end: display.text.length, scope: '' }] : [];
    return display;
}

Palette semantics, without a CSS parser

The pure syntaxColor lookup in themes.literate supplies the same scope colors as standalone HTML and live preview CSS. Unknown scopes reset to text, and dotted scopes use their base class. This adapter retains explicit publication typography: keywords and variables are bold; literals remain purple without forced bold. Comments, quotes and emphasis are italic, and strong is bold. Unlike screen CSS, LaTeX syntax links are not underlined. No palette is remapped, including dark palettes; this cleanup changes neither format's existing output styling.

<<publication highlighting styles>>=

export function syntaxStyle(scope: string, theme: LiterateTheme): {
    color: string; bold: boolean; italic: boolean;
} {
    const base = scope.split('.')[0];
    return { color: syntaxColor(scope, theme),
        bold: ['keyword', 'variable', 'template-variable', 'strong'].includes(base),
        italic: ['comment', 'quote', 'emphasis'].includes(base) };
}
