The headless generation engine

The engine turns a collection of literate documents into a complete generation plan. It does not read or write files, depend on VS Code, or consult platform state. CLI and editor adapters supply the inputs and decide when to write a successful result. This chapter is authoritative for src/engine.ts.

generateProject(documents, templates = {}) returns generated files and source-position diagnostics. Its central guarantee is atomic planning: any diagnostic makes the entire file list empty, including documentation HTML. A valid plan contains both tangled source and rendered documentation. GenerationResult.inspection also returns partial parser metadata on diagnostics: ordered accepted documents, sorted normalized referenced templates (even missing ones), and fragments in encounter order. Definitions include append fences; references exclude escaped tags and use original part offsets, not expanded text. All inspection coordinates are zero-based JavaScript string positions. GenerationResult.publication retains ordered accepted contributions, stable logical targets, and unexpanded code segments for future publication renderers. It survives diagnostics without changing existing source or HTML emission. parseProject(documents) exposes the shared accepted snapshot without generation policy: original sources, Markdown-it tokens, ordered Markdown/contribution blocks, inspection, publication links, and source/declaration diagnostics only.

The root fragment assembles the implementation in dependency order. The final fragment describes the generation phases; the preceding fragments provide shared contracts and helpers for both generation and its adapters.

Contracts at the adapter boundary

A SourceDocument supplies a workspace-relative POSIX path and source text. A GeneratedFile supplies a relative destination and its complete content. Templates arrive as an explicit mapping of paths to text, rather than being loaded implicitly. All mutable generation state belongs to a single call.

Diagnostic line and column coordinates are zero-based; columns count JavaScript string positions. Adapters may translate them for display without changing the engine contract. Internal fragment parts retain their own source locations, so an error in an appended part points back to that part's document. Markdown-it supplies parsing and rendering, while highlight.js handles known code languages. Adapters share the readonly discoveryExcludedDirectories list to avoid discovering sources in version control, dependency, build, and test-runtime directories.

Publication identities do not depend on presentation

Encode each UTF-16 code unit as four hexadecimal digits, preserving exact names, including case and Unicode distinctions. Hyphen separators cannot occur inside encoded components. Family targets use f- plus the encoded name; contributions use c-, the encoded name, canonical document path, and a one-based accepted ordinal local to that family and document. These namespaces need no Node APIs.

<<engine publication identity>>=
function publicationEncode(value: string): string {
    let encoded = '';
    for (let index = 0; index < value.length; index++) {
        encoded += value.charCodeAt(index).toString(16).padStart(4, '0');
    }
    return encoded;
}

Prose edits, shifted source lines, and unrelated contributions leave targets unchanged. Inserting or removing an earlier contribution of the same family in the same document can renumber later contributions. Renaming a family changes its targets; moving a contribution between documents changes its target. This policy promises deterministic collision-free identities, not arbitrary edit-stability, which would require explicit author IDs. Token indexes connect contributions to the existing document token stream but never define identity.

Paths and source text must survive parsing unchanged

safeRelativePath canonicalizes paths inside the workspace, rejecting absolute paths, backslashes, control characters, and parent traversal beyond the root. The policy is portable even when generation runs on a case-sensitive host: components cannot contain Windows-invalid characters (including colons used for alternate data streams), end in a dot or space, or use reserved device names such as CON, NUL.txt, or COM1. Device names are checked without regard to case, including extensions and Windows' reserved superscript digits. The navigation components . and .. are handled first, so parent traversal that remains within the workspace still normalizes safely.

Collision keys use locale-independent lowercase paths for sources, templates, and outputs. Output/input aliases, duplicate output aliases, and ancestor conflicts are rejected: a planned file cannot also be a directory containing another planned file or supplied input. This conservative lexical policy does not replace adapters' filesystem checks, including symbolic-link handling.

The shared header grammar distinguishes fragment definitions and appends from their output filename and optional settings. Empty output names are rejected later when collecting definitions. Actual NUL characters are rejected in source text before Markdown-it can normalize them into replacement characters, which would otherwise conceal invalid names. Their diagnostic coordinates are computed from the original text, including its original line endings.

<<engine path and source validation>>=

export function safeRelativePath(value: string): string | undefined {
    if (!value || /^(?:\/|[a-zA-Z]:)/.test(value) || /[\\\x00-\x1f]/.test(value)) { return undefined; }
    const parts: string[] = [];
    for (const part of value.split('/')) {
        if (!part || part === '.') { continue; }
        if (part === '..') {
            if (!parts.length) { return undefined; }
            parts.pop();
        } else {
            if (/[<>:"|?*]/.test(part) || /[. ]$/.test(part)) { return undefined; }
            const device = part.split('.')[0].replace(/ +$/, '');
            if (/^(?:con|prn|aux|nul|com[1-9¹²³]|lpt[1-9¹²³]|conin\$|conout\$)$/i.test(device)) { return undefined; }
            parts.push(part);
        }
    }
    return parts.length ? parts.join('/') : undefined;
}

Shared lexical contracts for editor symbols

The scanner returns whole-tag UTF-16 ranges, excluding reference operators. Escaped openers are consumed by the same regex as real tags, so generation and editor tools cannot disagree about whether a tag is a dependency. Operators remain available to generation for diagnostics, without entering rename ranges.

<<engine shared fragment scanning>>=
export interface FragmentTag { name: string; start: number; end: number; modifier?: string; }

export function scanFragmentTags(text: string): FragmentTag[] {
    const tags: FragmentTag[] = [];
    const pattern = /\\<<|<<([^<>\r\n]+)>>(=\+?|\+)?/g;
    let match: RegExpExecArray | null;
    while ((match = pattern.exec(text))) {
        if (match[1] === undefined) { continue; }
        tags.push({ name: match[1], start: match.index,
            end: match.index + match[1].length + 4, modifier: match[2] });
    }
    return tags;
}

Header offsets are relative to the supplied info string, not the fence marker. The anchored engine grammar remains the single source of truth; locate its tag after the optional language rather than searching for a possibly repeated name in the language or filename. Blank names are not declarations.

<<engine shared header parsing>>=
export interface FragmentHeader {
    name: string; language: string; append: boolean; remainder: string;
    tagStart: number; tagEnd: number;
}

export function parseFragmentHeader(info: string): FragmentHeader | undefined {
    const match = fragmentHeader.exec(info);
    if (!match || !match[2].trim()) { return undefined; }
    const afterLanguage = match[1] ? info.indexOf(match[1]) + match[1].length : 0;
    const tagStart = info.indexOf('<<', afterLanguage);
    return { name: match[2], language: match[1] || '', append: !!match[3], remainder: match[4],
        tagStart, tagEnd: tagStart + match[2].length + 4 };
}

One document order for generation and editor maps

Fragment appends make document order significant. The root index.literate comes first, followed by documents linked from it in link order, then all remaining documents sorted by normalized path. HTML links select the matching literate source; query strings and anchors do not affect selection. Repeated links do not give a document another position in the order.

orderSourceDocuments exposes this policy to editor adapters. It returns a new array containing the original objects and preserves all input documents. Generation, rather than this helper, owns duplicate and invalid-path checks. The standalone helper throws an ordinary Error for NUL-containing source.

Resolve the project theme without filesystem access

Only SETTINGS fences in the normalized root index.literate select a theme. Omission uses rosepine-dawn; repeated settings keep the last valid value, but all invalid values (including empty ones) remain diagnostics. Generation uses this same exported query once, so preview and generation share the policy.

<<engine project theme resolution>>=
export function resolveProjectTheme(documents: SourceDocument[]): { name: string; diagnostics: GenerationDiagnostic[] } {
    let name = defaultThemeName;
    const diagnostics: GenerationDiagnostic[] = [];
    const document = documents.find(value => safeRelativePath(value.path) === 'index.literate');
    if (!document) { return { name, diagnostics }; }
    const nul = sourceNulDiagnostic(document);
    if (nul) { return { name, diagnostics: [nul] }; }
    for (const token of new MarkdownIt().parse(document.text, {})) {
        if (token.type !== 'fence' || token.info.trim() !== 'SETTINGS') { continue; }
        token.content.split('\n').forEach((line: string, index: number) => {
            const match = /^\s*theme\s*=(.*)$/.exec(line);
            if (!match) { return; }
            const value = match[1].trim();
            if (getTheme(value)) { name = value; }
            else {
                diagnostics.push({ path: 'index.literate', line: (token.map?.[0] || 0) + index + 1,
                    column: 0, message: `Unknown theme: ${value}` });
            }
        });
    }
    return { name, diagnostics };
}

Templates are literal, single-pass substitutions

Source templates recognize [CODE]; HTML templates recognize [CONTENT] and [AUTHORS] and [THEME]. A callback replaces every matching original placeholder literally. Inserted text is never scanned again, so dollar replacement sequences and placeholders inside generated code, author metadata, or rendered prose cannot trigger a second substitution. Unknown placeholders remain untouched.

<<engine literal template substitution>>=

function substitute(template: string, values: Record<string, string>): string {
    return template.replace(/\[(CODE|CONTENT|AUTHORS|THEME)\]/g, (match, key: string) =>
        Object.prototype.hasOwnProperty.call(values, key.toLowerCase()) ? values[key.toLowerCase()] : match);
}

Collect definitions and reserve every destination

Named fences use a language followed by a colon, a double-chevron name, and = for a definition or =+ for an ordered append; a language may be omitted. Appends require an earlier definition and cannot change its output or template. Top-level names end in .* and require a filename terminated by a space and $, optionally followed by template=path.

Depth-first expansion detects missing fragments and cycles, memoizes completed expansions, and checks even unused fragments. It has no arbitrary pass-count cutoff. Reference diagnostics use the originating part's position, including the reference's column within its code line.
