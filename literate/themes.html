Palette snapshot

Each compact row contains a canonical name followed by the 13 colors in colorKeys order. For the 69 Base46 palettes these are, respectively: black black2 one_bg white light_grey grey green blue orange red purple cyan yellow. The first ten match theme_store.zig's mappedColors semantic tokens exactly; syntax colors retain the corresponding Base46 fields. RGB spelling and case are preserved, with no contrast adjustment or interpolation.

hermonica uses draw.zig defaults: bg surface surface_2 text muted line accent blue orange red zone_3 zone_6 zone_7. The last three are its existing purple, cyan and yellow/olive zone colors, not newly invented RGB values. dark compares background and text relative luminance (sRGB linearization), rather than guessing from the palette name. Muted and syntax colors intentionally retain the original contrast characteristics; the catalogue does not claim WCAG compliance.

Catalogue and exact lookup

The array, entries and colors are frozen to protect the shared snapshot. A Map also makes prototype names such as constructor and __proto__ ordinary misses.

<<Theme catalogue>>=
function luminance(hex: string): number {
    const channels = [1, 3, 5].map(offset => {
        const channel = parseInt(hex.slice(offset, offset + 2), 16) / 255;
        return channel <= 0.04045 ? channel / 12.92 : Math.pow((channel + 0.055) / 1.055, 2.4);
    });
    return channels[0] * 0.2126 + channels[1] * 0.7152 + channels[2] * 0.0722;
}

export const themes: readonly LiterateTheme[] = Object.freeze(paletteRows.map(row => {
    const [name, ...values] = row.split(' ');
    const colors = {} as LiterateTheme['colors'];
    colorKeys.forEach((key, index) => { colors[key] = values[index]; });
    return Object.freeze({ name, dark: luminance(colors.background) < luminance(colors.text),
        colors: Object.freeze(colors) });
}));

const themesByName = new Map(themes.map(theme => [theme.name, theme]));

export function getTheme(name: string): LiterateTheme | undefined {
    return themesByName.get(name);
}

Shared syntax colors and format policy

These ordered groups are the single scope-to-palette source for document CSS and publication syntax. Keeping link separate preserves the existing CSS order. Only base scopes select colors: highlight.js emits title.function as classes hljs-title function_, while publication receives the dotted scope directly. Unknown scopes (including prototype names) reset to text. No runtime imports, CSS parsing, palette adjustment or language dependency are needed here.

<<Theme syntax scope groups>>=
interface SyntaxColorGroup {

    color: keyof LiterateTheme['colors'];
}

    { scopes: 'string regexp addition', color: 'accent' },
    { scopes: 'number symbol bullet', color: 'warning' },
    { scopes: 'title section built_in type', color: 'information' },
    { scopes: 'attr attribute variable template-variable', color: 'cyan' },
    { scopes: 'comment quote', color: 'muted' },
    { scopes: 'meta doctag', color: 'yellow' },

    group.scopes.split(' ').map(scope => [scope, group.color] as const)));

    return theme.colors[syntaxColorKeys.get(scope.split('.')[0]) ?? 'text'];
}

Colors are shared; typography remains a format adapter's responsibility. Standalone HTML and the live preview both consume themeCss (the preview's applyTheme installs it even without diagrams). Preserve screen comment/quote italics, link underlines and the separate emphasis/strong rules. Do not add publication's keyword/variable bold policy or reset host font inheritance here. LaTeX deliberately supplies its own weights and never underlines syntax links.

<<Theme syntax adapters>>=
function syntaxColorCss(): string {
    return syntaxColorGroups.map(group => {
        const selectors = group.scopes.split(' ')
            .map(scope => `.literate-document .hljs-${scope}`).join(', ');
        const decoration = group.scopes === 'comment quote' ? ' font-style: italic;'
            : group.scopes === 'link' ? ' text-decoration: underline;' : '';
        return `${selectors} { color: var(--literate-${group.color});${decoration} }`;
    }).join('\n');
}

Safe custom properties

Only fixed property names and six-digit RGB literals are serialized, even when a caller supplies a custom structural LiterateTheme. Invalid colors throw rather than becoming CSS, HTML or Mermaid configuration injection. Theme names are never interpolated into output. Extra object properties are ignored.

<<Theme serialization>>=
function checkedColors(theme: LiterateTheme): LiterateTheme['colors'] {
    const colors = {} as LiterateTheme['colors'];
    for (const key of colorKeys) {
        const value = theme.colors[key];
        if (typeof value !== 'string' || value.length !== 7 || !/^#[0-9a-fA-F]{6}$/.test(value)) {
            throw new Error(`Invalid theme color: ${key}`);
        }
        colors[key] = value;
    }
    return colors;
}

export function themeVariables(theme: LiterateTheme): string {
    const colors = checkedColors(theme);
    return colorKeys.map(key => {
        const property = key.replace(/[A-Z]/g, letter => `-${letter.toLowerCase()}`);
        return `--literate-${property}: ${colors[key]};`;
    }).join('\n');
}
