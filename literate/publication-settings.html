Publication font settings

This chapter owns src/publication-settings.ts and its headless tests. It reads only root index.literate SETTINGS tokens from a ParsedProject; parseProject has already canonicalized paths with safeRelativePath. Chapter settings and unrelated keys (including theme) are not ours. Keys and on/off are case-sensitive.

Code defaults to Lilex Nerd Font, whose regular, bold, italic and bold-italic files all report that exact family via fc-scan. Native italic faces avoid requiring synthesis for the default code comments.

This is font selection, not font bundling. There is no filesystem access, font lookup, global installation, or runtime dependency. Renderers remain responsible for applying the selected families and ligature policy. In particular, off calls for disabling calt (-calt), verified for the actual D2 font, rather than merely disabling liga. This chapter does not change a renderer or CLI.

Public contract

All five families are resolved strings. Omitted notes inherit the final selected body family, whereas fragments default independently to Monofur. Diagnostics here describe settings only: they do not copy project.diagnostics. Callers must still gate rendering on source diagnostics through preparation (preparePandoc); a settings result alone is not permission to render. Source NUL rejection belongs to the existing parser, before Markdown can replace NUL with a replacement glyph.

<<publication settings contract>>= 
import type { GenerationDiagnostic, ParsedProject } from './engine';

export interface PublicationFonts {
    body: string;
    heading: string;
    code: string;
    fragment: string;
    note: string;
}
export interface PublicationSettingsResult {
    fonts: PublicationFonts;
    codeLigatures: boolean;
    diagnostics: GenerationDiagnostic[];
}

Scan in authored order

Each call starts fresh. A missing root is valid and yields defaults. We consume the existing fence tokens, including fences inside Markdown containers, without reparsing source or treating ordinary code blocks as settings.

<<publication settings resolver>>= 
export function resolvePublicationSettings(project: ParsedProject): PublicationSettingsResult {
    const fonts: PublicationFonts = {
        body: 'Latin Modern Roman', heading: 'Monofur Nerd Font',
        code: 'Lilex Nerd Font', fragment: 'Monofur Nerd Font', note: ''
    };
    let codeLigatures = true;
    let explicitNote = false;
    const diagnostics: GenerationDiagnostic[] = [];
    const document = project.documents.find(value => value.path === 'index.literate');
    for (const token of document?.tokens ?? []) {
        if (token.type !== 'fence' || token.info.trim() !== 'SETTINGS') { continue; }
        token.content.split('\n').forEach((line: string, index: number) => {
            const match = /^\s*(font-body|font-heading|font-code|font-fragment|font-note|font-code-ligatures)\s*=(.*)$/.exec(line);
            if (!match) { return; }
            const key = match[1];
            const value = match[2].trim();

Family values use the same simple ASCII grammar as the existing LaTeX fontName: 1–100 letters, digits, spaces, dots or hyphens, starting with a letter or digit. Whitespace around values is trimmed; empty names, paths and TeX syntax are rejected. Last valid wins, but every invalid occurrence remains a diagnostic, just as for theme settings. Coordinates are zero-based: the fence map starts at its opener, so content line zero is source line map[0] + 1, also within lists and quotes.

<<publication settings resolver>>=+ 
            const report = (message: string): void => {
                diagnostics.push({ path: document!.path,
                    line: (token.map?.[0] ?? 0) + index + 1, column: 0, message });
            };
            if (key === 'font-code-ligatures') {
                if (value === 'on' || value === 'off') { codeLigatures = value === 'on'; }
                else { report(`Invalid ${key}: expected on or off`); }
            } else if (/^[A-Za-z0-9][A-Za-z0-9 .-]{0,99}$/.test(value)) {
                const role = key.slice(5) as keyof PublicationFonts;
                fonts[role] = value;
                if (role === 'note') { explicitNote = true; }
            } else {
                report(`Invalid ${key}: font must be a simple family name (1–100 ASCII characters)`);
            }
        });
    }
    if (!explicitNote) { fonts.note = fonts.body; }
    return { fonts, codeLigatures, diagnostics };
}

<<publication settings test setup>>= 
import assert = require('node:assert/strict');
import { test } from 'node:test';
import { parseProject } from '../../engine';
import { preparePandoc } from '../../publication-pandoc';
import { resolvePublicationSettings } from '../../publication-settings';
import type { PublicationFonts, PublicationSettingsResult } from '../../publication-settings';

const defaults: PublicationFonts = {
    body: 'Latin Modern Roman', heading: 'Monofur Nerd Font',
    code: 'Lilex Nerd Font', fragment: 'Monofur Nerd Font', note: 'Latin Modern Roman'
};
const fence = (content: string, info = 'SETTINGS') => '```' + info + '\n' + content + '\n```\n';
function resolve(text: string, path = 'index.literate'): PublicationSettingsResult {
    const project = parseProject([{ path, text }]);
    assert.deepEqual(project.diagnostics, []);
    return resolvePublicationSettings(project);
}

Defaults are per-call values, and only the canonical, exact-case root participates. A chapter named index.literate is still not the root.

<<publication settings default tests>>= 
test('publication settings defaults and root-only scope', () => {
    const expected = { fonts: defaults, codeLigatures: true, diagnostics: [] };
    assert.deepEqual(resolvePublicationSettings(parseProject([])), expected);
    assert.deepEqual(resolve(''), expected);
    for (const path of ['chapter.literate', 'chapters/index.literate', 'Index.literate']) {
        assert.deepEqual(resolve(fence('font-body=Other\nfont-code-ligatures=bad'), path), expected);
    }
    const project = parseProject([
        { path: 'chapter.literate', text: fence('font-body=Chapter\nfont-note=') },
        { path: './parts/../index.literate', text: fence('font-body=Root') }
    ]);
    assert.deepEqual(project.diagnostics, []);
    assert.equal(resolvePublicationSettings(project).fonts.body, 'Root');
    assert.deepEqual(resolvePublicationSettings(project).diagnostics, []);
    const rejected = parseProject([{ path: '.\\index.literate', text: fence('font-body=Wrong') }]);
    assert.ok(rejected.diagnostics.some(d => d.message === 'Invalid source path'));
    assert.deepEqual(resolvePublicationSettings(rejected), expected);
    const changed = resolve('');
    changed.fonts.body = 'Changed';
    assert.deepEqual(resolve(''), expected);
});

Every role accepts trimmed names. Note inheritance is delayed across SETTINGS blocks, but an explicit valid note survives subsequent invalid note values.

test('publication settings select all roles and delay note inheritance', () => {
    const result = resolve(fence('font-body = Body 2.0\nfont-heading= Heading-Font \n' +
        'font-code= Code Font \nfont-fragment= Fragment Font\nfont-code-ligatures= off '));

        code: 'Code Font', fragment: 'Fragment Font', note: 'Body 2.0' },

    const inherited = resolve(fence('font-note=\nfont-body=First') + fence('font-body=Last'));

    const explicit = resolve(fence('font-note=Notes') + fence('font-body=Last\nfont-note=bad/path'));

Invalid repetitions never erase a valid value or an earlier diagnostic. Valid ligature values likewise override only the selected value, not diagnostic history.

The grammar is deliberately narrower than fontspec input; no TeX escaping or path interpretation is attempted. All five family keys share this validation.

<<publication settings validation tests>>=+ 
test('publication settings enforce the simple ASCII family grammar', () => {
    const invalid = ['', '   ', 'A'.repeat(101), '.Font', '-Font', 'École', 'A_B',
        'A/B', 'A\\B', 'A{B}', 'A%B', 'A#B', 'A$B', 'A&B', 'A~B', 'A^B', 'A[B]', 'A\tB'];
    for (const role of ['body', 'heading', 'code', 'fragment', 'note'] as const) {
        for (const value of invalid) {
            const result = resolve(fence('font-' + role + '=' + value));
            assert.equal(result.fonts[role], defaults[role], role + ': ' + value);
            assert.equal(result.diagnostics.length, 1, role + ': ' + value);
        }
        for (const value of ['A', '0', 'A'.repeat(100), 'Family 2.0-Pro']) {
            const result = resolve(fence('font-' + role + '=  ' + value + '  '));
            assert.equal(result.fonts[role], value);
            assert.deepEqual(result.diagnostics, []);
        }
    }
});

Unrelated SETTINGS and non-SETTINGS text are ignored, including differently cased keys, ordinary fences and indented code. Container fences remain ordinary settings.

test('publication settings map zero-based lines across newlines and containers', () => {
    const lines = ['# Title', '', '> ```SETTINGS', '> font-body=Quoted', '> font-heading=',
        '> ```', '', '- item', '', '  ```SETTINGS', '  font-code-ligatures=off',
        '  font-note=bad/path', '  ```'];
    for (const newline of ['\n', '\r\n', '\r']) {

        assert.equal(result.fonts.body, 'Quoted');
        assert.equal(result.fonts.note, 'Quoted');
        assert.equal(result.codeLigatures, false);
        assert.deepEqual(result.diagnostics.map(d => [d.line, d.column]), [[4, 0], [11, 0]]);

Source diagnostics remain owned by the parser and the preparation gate. Resolving settings neither duplicates nor mutates them, even when a rejected source is NUL-bearing.

<<publication settings source tests>>=+ 
test('publication settings leave source diagnostics to the preparation gate', () => {
    const project = parseProject([{ path: 'index.literate', text: fence('font-body=A\0B') }]);
    assert.ok(project.diagnostics.some(d => /NUL/.test(d.message)));
    const before = JSON.stringify(project);
    assert.deepEqual(resolvePublicationSettings(project), {
        fonts: defaults, codeLigatures: true, diagnostics: []

    assert.equal(prepared.document, undefined);
    assert.deepEqual(prepared.diagnostics, project.diagnostics);
