Publication and screen integration boundary

M1 establishes a tested correspondence, not a screen migration. generateProject produces HTML from its collected Markdown tokens; the VS Code contribution markdown.markdownItPlugins loads the extendMarkdownIt hook returned by activate. That hook wraps the host's fence renderer. The extension's private parser is not a substitute for testing this path.

Neither screen path currently emits fragment IDs or reference links. A publication contribution maps to a screen block by canonical document path and its accepted fence token index (then its ordinal among fragment blocks in that document). Its family target identifies the base plus all additions; it is not a screen URL. LaTeX encodes that target again as lit- plus fixed-width UTF-16 hex. Heading IDs are a separate boundary: HTML has none; preview delegates them to VS Code.

These tests drive the real engine and activated plugin, with only the VS Code API mocked by our existing fixture. They inspect actual labels, code, delegation and source maps, not equality of two model snapshots. The optional Pandoc test drives the production LaTeX renderer and process adapter on the same inputs. No renderer is replaced with a test implementation. This is not a VS Code host/browser click or source-synchronization end-to-end test.

A fixture with independent expectations

Use punctuation-distinct families, repeated forward references, an escaped tag, an ordinary fence, nested declarations and additions in two chapters. Supplying documents out of order exercises chapter ordering rather than input-array order. The expected source is written independently, so a renderer that expands fragment uses, drops additions or mixes up the two names cannot pass by agreeing with itself.

function textContent(html: string): string {
    return html.replace(/<[^>]*>/g, '').replace(/&(lt|gt|amp|quot|#39);/g,

Our extractor deliberately understands only these controlled fragment wrappers, not arbitrary HTML. We assert wrapper counts as well, so extraction cannot quietly skip a malformed block. Ordinals are a test observation, not new persistent IDs.

function blocks(html: string) {
    const found = [...html.matchAll(/<div class="codefragment">\s*<div class="fragmentname">([^]*?)<\/div>\s*<div class="code">([^]*?)<\/div>\s*<\/div>/g)];
    assert.equal(found.length, (html.match(/class="codefragment"/g) || []).length);
    return found.map(match => ({ label: textContent(match[1]).trim(), code: match[2] }));
}

Activate the actual preview hook

Install a real Markdown-it renderer with highlight.js as its host highlighter. Observe delegation before the plugin wraps it: source maps and token positions must survive, while escaped literal openers are unescaped only in the display copy. The grabber environment retains the original tokens for comparison.

<<publication screen preview>>= 
async function preview() {
    const f = fixture();
    const subscriptions: vscode.Disposable[] = [];
    const api = await f.extension.activate({ subscriptions } as unknown as vscode.ExtensionContext);
    const md = new MarkdownIt({ highlight: (code, language) =>
        hljs.getLanguage(language) ? hljs.highlight(code, { language }).value : '' });
    const delegated: { index: number; token: Token }[] = [];
    const original = md.renderer.rules.fence!;
    md.renderer.rules.fence = (tokens, index, options, env, renderer) => {
        delegated.push({ index, token: tokens[index] });
        return original(tokens, index, options, env, renderer);
    };
    api.extendMarkdownIt(md);
    return { md, delegated, dispose: () => subscriptions.forEach(value => value.dispose()) };
}

Map emitted blocks to shared targets

Check a screen block against its independently expected family, operator and unexpanded body, then join its source token to the publication target. We do not invent an anchor on either screen. Both absence of IDs and absence of links are intentional M1 boundary assertions; M2 must replace them with destination tests.

<<publication screen mapping checks>>= 
function checkBlocks(html: string, path: string, model: PublicationModel, format: 'html' | 'preview') {
    const rendered = blocks(html);
    const wanted = expected.get(path)!;
    const parts = model.contributions.filter(part => part.definition.path === path);
    assert.equal(rendered.length, wanted.length);
    assert.equal(parts.length, wanted.length);
    return rendered.map((block, index) => {
        const want = wanted[index], part = parts[index];
        const family = model.fragments.find(value => value.name === want.name)!;
        assert.ok(family);
        assert.equal(part.kind, want.kind);
        assert.equal(part.fragmentTarget, family.target);
        assert.ok(family.contributions.includes(part.target));
        const label = `<<${want.name}>>=${want.kind === 'append' ? '+' : ''}`;
        const suffix = want.name === 'main.*' ? (format === 'html' ? ' result.txt $' : ' result.txt') : '';
        assert.equal(block.label, label + suffix);
        const code = block.code.match(/<code\b[^>]*>([^]*?)<\/code>/);
        assert.ok(code);
        assert.equal(textContent(code[1]), want.body);
        assert.doesNotMatch(block.code, /<(?:a)\b|\bid=/);
        return part.target;
    });
}

Decoration is not reference semantics

Post-highlight screen decoration still mistakes an escaped tag for a visual tag. That is a known M2 gap, not a publication reference. An ordinary fence is not decorated at all. Assert the distinction explicitly rather than deleting the literal from the fixture or treating every span as a resolved link.

<<publication screen literal boundary>>= 
test('screen tag decoration is explicitly not a semantic reference or link', async () => {
    const inputs = documents(), generated = generateProject(inputs), p = await preview();
    try {
        const source = inputs.find(doc => doc.path === 'index.literate')!;
        const outputs = [generated.files.find(file => file.path === 'index.html')!.content,
            p.md.render(source.text, {})];
        for (const html of outputs) {
            const tags = [...blocks(html)[0].code.matchAll(/<span class="literate-tag-name">([^]*?)<\/span>/g)];
            assert.deepEqual(tags.map(match => textContent(match[1])),
                ['<<a/b>>', '<<a-b>>', '<<a/b>>', '<<literal>>']);
            assert.ok(html.includes(escape('<<ordinary>>')));
            assert.ok(!tags.some(match => match[1].includes('ordinary')));
            assert.doesNotMatch(blocks(html)[0].code, /<a\b/);
        }
        assert.equal(references(generated.publication).length, 3);
    } finally { p.dispose(); }
});

Follow the same targets through real Pandoc

Decode emitted LaTeX destinations rather than recomputing IDs with the production encoder. Every family/contribution must have exactly one label; reference macros must target precisely the three semantic occurrences, never the escaped lookalike. The renderer creates reference commands before highlighting; screen decoration is not an input to that process. Pandoc and the CLI adapter are real in this opt-in test.

<<publication screen latex mapping>>= 
function logicalTarget(encoded: string): string {
    assert.match(encoded, /^lit-(?:[0-9a-f]{4})+$/);
    return encoded.slice(4).match(/.{4}/g)!.map(unit => String.fromCharCode(parseInt(unit, 16))).join('');
}

The normal headless suite still needs no external tools. The full real-Pandoc validation enables this check alongside existing process lifecycle tests.

<<publication screen latex test>>= 
for (const [name, inputs, count] of [['plain', documents(), 3], ['highlighted', highlightedDocuments(), 1]] as const) {
test(`real Pandoc LaTeX labels and reference macros map ${name} screens to shared targets`,
    { skip: process.env.LITERATE_TEST_PANDOC !== '1' }, async () => {
        const parsed = parseProject([...inputs]);
        const result = await renderLatex(parsed, {}, runPandoc);
        assert.deepEqual(result.diagnostics, []);
        assert.ok(result.latex);
        const labels = [...result.latex.matchAll(/\\label\{(lit-[0-9a-f]+)\}/g)].map(match => logicalTarget(match[1]));
        const targets = [...parsed.publication.fragments, ...parsed.publication.contributions].map(value => value.target);
        for (const target of targets) { assert.equal(labels.filter(label => label === target).length, 1, target); }
        const commands = [...result.latex.matchAll(/\\newcommand\{\\LitReference[A-Z]+\}[^\n]+/g)];
        assert.equal(commands.length, count);
        const destinations = commands.map(command => {
            const link = command[0].match(/\\hyperref\[(lit-[0-9a-f]+)\]/)!;
            assert.ok(link);
            assert.ok(command[0].includes(`\\pageref*{${link[1]}}`));
            return logicalTarget(link[1]);
        });
        assert.deepEqual(destinations, references(parsed.publication).map(ref => {
            assert.equal(ref.resolution.kind, 'resolved');
            return ref.resolution.kind === 'resolved' ? ref.resolution.target : assert.fail('unresolved');
        }));
    });
