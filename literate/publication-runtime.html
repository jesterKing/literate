Shipping a publication runtime

An installed extension is not a development checkout. Publication ships three JavaScript files: a CommonJS helper, an ESM browser worker, and an offline Mermaid IIFE. The helper's owner supplies src/publication-helper.ts, restricts requests to latex and pdf, and calls the shared CLI runner with a source snapshot. Neither the editor nor the helper loads the source-generation toolchain.

The extension launches the helper with an explicitly selected compatible Node executable, not Electron's executable. Pandoc, TeX, and a sandbox-capable Chromium remain system dependencies. This chapter builds code; it neither locates those tools nor downloads them.

One build contract, three entry points

build:publication builds all three files. The existing CLI uses worker mode, which builds the browser and worker without requiring the extension helper. Browser mode preserves the standalone browser build. Paths are anchored to the build script's project, never the caller's current directory. Exported functions allow tests to build into a private directory without replacing release files.

Only the build process imports esbuild and the full Puppeteer API. The full API is needed to take a launch-argument snapshot, not to launch or install a browser. The runtime graph is independently checked after bundling.

The browser entry and launch snapshot are version-specific compatibility boundaries. An upgrade must change these pins deliberately and rerun the real browser family and isolation tests. Checking both the manifest declaration and the installed metadata catches stale installs as well as accidental ranges.

Not every package exports package.json or a CommonJS entry. Resolve with ESM import conditions, then start at that entry and walk up to its own named manifest instead of assuming a particular node_modules layout. This lookup belongs exclusively to the build, not to any shipped file.

<<publication dependency metadata>>=
async function dependencyMetadata(name) {
    let directory = path.dirname(fileURLToPath(import.meta.resolve(name)));
    for (;;) {
        try {
            const metadata = await json(path.join(directory, 'package.json'));
            if (metadata.name === name) { return metadata; }
        } catch (error) {
            if (error.code !== 'ENOENT') { throw error; }
        }
        const parent = path.dirname(directory);
        if (parent === directory) { throw new Error(`Cannot find metadata for ${name}`); }
        directory = parent;
    }
}

The Node floor matches Puppeteer Core. Builds use a real Node process too; Electron's embedded version is not a substitute for the supported runtime.

<<publication version validation>>=
export async function validatePublicationVersions(root = projectRoot) {
    const [major, minor] = process.versions.node.split('.').map(Number);
    if (process.versions.electron || major < 22 || (major === 22 && minor < 12)) {
        throw new Error('Publication builds require external Node >=22.12');
    }
    const manifest = await json(path.join(root, 'package.json'));
    for (const [name, version] of Object.entries(publicationPins)) {
        const declared = manifest.dependencies?.[name] ?? manifest.devDependencies?.[name];
        const installed = (await dependencyMetadata(name)).version;
        if (declared !== version || installed !== version) {
            throw new Error(`Publication requires ${name} ${version}; declared ${declared}, installed ${installed}`);
        }
    }
}

Puppeteer can alter default arguments from environment variables. Refuse the two pinned-version overrides rather than embedding a disabled sandbox or experimental features into every installation. No profile or debug endpoint enters the snapshot: those belong to each individual worker invocation.

<<publication launch snapshot>>=
export async function publicationDefaultArgs() {
    for (const name of ['PUPPETEER_DANGEROUS_NO_SANDBOX', 'PUPPETEER_TEST_EXPERIMENTAL_CHROME_FEATURES']) {
        if (process.env[name] === 'true') { throw new Error(`Unset ${name} before building publication`); }
    }
    const { default: puppeteer } = await import('puppeteer-core');
    const args = await puppeteer.defaultArgs({ headless: true });
    if (!Array.isArray(args) || !args.includes('--headless=new')
        || args.some(arg => typeof arg !== 'string'
            || /^--(?:no-sandbox|disable-setuid-sandbox|user-data-dir|remote-debugging)/.test(arg))) {
        throw new Error('Unexpected pinned Puppeteer launch arguments');
    }
    return args;
}

Boundaries enforced at build time

The shared CLI retains its self-check command for developers. The publication helper never permits that command, so this build replaces only the self-hosting module with a fail-closed stub. It does not externalize TypeScript or esbuild and hope that an installed package will never resolve them. Normal CLI builds do not use this plugin. A separate CLI executable entry must own auto-execution; bundling a require.main === module guard from the shared runner would invoke it twice.

<<publication self hosting boundary>>=
function publicationOnly() {
    return { name: 'publication-only', setup(builder) {
        builder.onResolve({ filter: /^\.\/self-hosting(?:\.js)?$/ }, () => ({
            path: 'self-hosting-disabled', namespace: 'publication'
        }));
        builder.onLoad({ filter: /.*/, namespace: 'publication' }, () => ({
            contents: 'export function verifySelfHosting() {'
                + ' throw new Error("Self-hosting is unavailable in the publication helper"); }',
            loader: 'js'
        }));
    } };
}

A successful compilation alone is insufficient. Each runtime is exactly one file; its only unresolved imports may be Node builtins, and the browser has none. Package metadata resolution, native optional addons, browser installers and source toolchains cannot hide behind lazy imports. The disabled browser-manager module has a different name and is the only permitted discovery substitute.

<<publication graph validation>>=
export function assertPublicationGraph(metadata, platform) {
    const outputs = Object.values(metadata.outputs);
    if (outputs.length !== 1) { throw new Error('Publication bundles must contain exactly one output'); }
    for (const dependency of outputs[0].imports) {
        if (dependency.kind === 'require-resolve' || platform === 'browser' || !isBuiltin(dependency.path)) {
            throw new Error(`Unbundled publication dependency: ${dependency.path}`);
        }
    }
    for (const input of Object.keys(metadata.inputs)) {
        const name = input.replaceAll('\\', '/');
        if (/(?:^|\/)node_modules\/(?:typescript|esbuild|webpack|puppeteer|@puppeteer\/browsers)(?:\/|$)/.test(name)
            || /(?:^|\/)src\/(?:self-hosting\.ts|build-publication\.mjs)$/.test(name)
            || /puppeteer-core\/lib\/puppeteer\/(?:node\/PuppeteerNode|node\/ChromeLauncher|node\/BrowserLauncher|puppeteer-core)\.js$/.test(name)) {
            throw new Error(`Forbidden publication build input: ${input}`);
        }
    }
}

Build in memory and validate before writing. Legal comments stay inside each bundle rather than in unshipped sidecars. Metafiles remain developer evidence in out, excluded by the VSIX allowlist; the three runtime files require no maps, chunks, metadata files, or package directories alongside them.

<<publication bundle preparation>>=
async function prepareBundle(root, outdir, name, options) {
    const outfile = path.join(outdir, name);
    const result = await build({
        absWorkingDir: root, bundle: true, minify: true, legalComments: 'eof',
        metafile: true, write: false, logLevel: 'error', outfile, ...options
    });
    assertPublicationGraph(result.metafile, options.platform);
    if (result.outputFiles.length !== 1) { throw new Error(`Unexpected sidecar for ${name}`); }
    return [
        { path: outfile, contents: result.outputFiles[0].contents },
        { path: outfile.replace(/\.(?:cjs|mjs|js)$/, '.meta.json'),
            contents: JSON.stringify(result.metafile, null, 2) + '\n' }
    ];
}

Mermaid's lazy imports must become deferred code inside the one browser IIFE, not runtime chunks. This retains all supported families and both pinned plugins.

ws has optional native accelerators. Compile those branches away instead of shipping native binaries or permitting ambient package resolution. Its remaining CommonJS builtin imports need createRequire inside the ESM worker. Even the connect-only entry has a channel-discovery branch, so the manager alias is required as well as the smaller Puppeteer entry.

<<publication worker build>>=
function prepareWorker(root, outdir, args) {
    return prepareBundle(root, outdir, 'publication-mermaid-worker.mjs', {
        entryPoints: ['src/publication-mermaid-worker.mjs'],
        platform: 'node', format: 'esm', target: 'node22.12',
        banner: { js: esmRequire },
        define: {
            PUBLICATION_CHROMIUM_DEFAULT_ARGS: JSON.stringify(args),
            'process.env.WS_NO_BUFFER_UTIL': '"1"',
            'process.env.WS_NO_UTF_8_VALIDATE': '"1"'
        },
        alias: { '@puppeteer/browsers': path.join(root, 'src/publication-browser-manager-disabled.mjs') }
    });
}

Markdown parsing, highlighting and the shared exporter are bundled into the helper. There are no package externals. The helper owns the request protocol; this builder neither rewrites its implementation nor invents another exporter.

<<publication helper build>>=

No build output is replaced if a dependency check or any compilation fails. Worker mode intentionally includes the browser bundle, matching the existing CLI build contract. Its return value lists runtime files and excluded build evidence.

<<publication build orchestration>>=
export async function buildPublication({ root = projectRoot, outdir, mode = 'publication' } = {}) {
    if (!['publication', 'worker', 'browser'].includes(mode)) {
        throw new Error(`Unknown publication build mode: ${mode}`);
    }
    root = path.resolve(root);
    outdir = path.resolve(outdir ?? path.join(root, 'out'));
    await validatePublicationVersions(root);
    const args = mode === 'browser' ? undefined : await publicationDefaultArgs();
    const files = await prepareBrowser(root, outdir);
    if (args) { files.push(...await prepareWorker(root, outdir, args)); }
    if (mode === 'publication') { files.push(...await prepareHelper(root, outdir)); }
    await fs.mkdir(outdir, { recursive: true });
    for (const file of files) { await fs.writeFile(file.path, file.contents); }
    return files.map(file => file.path);
}

Importing the builder is side-effect free: tests can call its checks directly. Only the dedicated executable path invokes a build. Unknown arguments are errors, not a silent fallback to an incomplete package.

<<publication build entry>>=
if (process.argv[1] && pathToFileURL(path.resolve(process.argv[1])).href === import.meta.url) {
    const args = process.argv.slice(2);
    const mode = args.length === 0 ? 'publication'
        : args.length === 1 && args[0] === '--worker' ? 'worker'
        : args.length === 1 && args[0] === '--browser' ? 'browser' : undefined;
    if (!mode) {
        console.error('Usage: node src/build-publication.mjs [--worker|--browser]');
        process.exitCode = 1;
    } else {
        buildPublication({ mode }).catch(error => {
            console.error(`Publication build failed: ${error.message}`);
            process.exitCode = 1;
        });
    }
}

A connection adapter, not a launcher

The worker already owns Chromium's process and its loopback endpoint. It needs only defaultArgs() and connect(), which also remain injectable in worker tests. This adapter does not offer installation, channels, executable discovery, or Puppeteer's detached launcher. The pinned browser entry is an explicit upgrade boundary, not a general-purpose replacement for Puppeteer Core.

Only fixed headless operation with an absolute private profile is supported. Caller flags cannot override the profile or remove sandboxing. The worker adds its loopback debugging flags and resource restrictions through args. Return a fresh array: one worker must not mutate the defaults of another.

<<publication adapter arguments>>=
export function defaultArgs(options) {
    if (options.headless !== true || !path.isAbsolute(options.userDataDir ?? '')
        || /[\u0000-\u001f]/.test(options.userDataDir) || !Array.isArray(options.args)
        || options.args.some(arg => typeof arg !== 'string' || !arg.startsWith('--')
            || /^--(?:no-sandbox|disable-setuid-sandbox|user-data-dir)(?:=|$)/.test(arg))) {
        throw new Error('Publication requires sandboxed headless Chromium and a private absolute profile');
    }
    return [...PUBLICATION_CHROMIUM_DEFAULT_ARGS,
        `--user-data-dir=${options.userDataDir}`, ...options.args];
}

Connect only to the endpoint announced by the owned process. Rejecting alternate connection modes here prevents accidental entry into browser-channel discovery; the build alias is a second fail-closed boundary for upstream changes.

<<publication adapter connection>>=
export function connect(options) {
    if (!/^ws:\/\/127\.0\.0\.1:\d+\/devtools\/browser\/[\w-]+$/.test(options.browserWSEndpoint ?? '')
        || Object.keys(options).some(key => !['browserWSEndpoint', 'protocolTimeout'].includes(key))) {
        throw new Error('Publication connects only to its owned loopback Chromium endpoint');
    }
    return puppeteer.connect(options);
}

The pinned connection code imports two enum bindings and two discovery functions. Enum access also fails closed; no fake channel or platform value can appear valid. An upstream addition of a named import fails the bundle until reviewed.

Installation and verification

Only the three runtime filenames are added to the VSIX allowlist. The build script and adapters are development inputs, not files to resolve at runtime. The worker statically imports Mermaid's package metadata so esbuild embeds its version; it reads only the sibling browser bundle on disk.

A release check must run the packaged helper from a relocated directory with the checkout and its dependencies inaccessible, then exercise real sandboxed Chromium. Metafile checks establish dependency closure, not browser compatibility or process cleanup. Keep the existing family, security, CLI and cancellation tests. PDF book compilation additionally requires the user's complete system TeX installation. The build preserves upstream legal comments; THIRD_PARTY_NOTICES.md supplies source attribution and the MIT and Apache license texts for the runtime boundary.
