A browser that produces assets

Chromium supplies SVG layout and PDF vector printing; it does not typeset the book. The worker loads the bundled Mermaid distribution through a connect-only Puppeteer adapter, excluding browser management and download code. Each diagram gets a new browser context, preventing one diagram's DOM and Mermaid counters from affecting another. The controller owns the deadline, process group and temporary directory.

Complete offline renderer graph

Mermaid distributes renderer definitions as lazy ESM chunks. Bundling the complete ESM graph into one IIFE preserves their deferred initialization without making network requests when a family is first used. ZenUML needs a separately registered plugin; tidy-tree supplies an optional layout, not a new diagram family. Their pinned packages are the same integrations offered by the Mermaid CLI. The plugin's prebundled ESM distribution avoids importing its Node-facing rendering helpers.

The pinned ZenUML definition injects CSS containing a neon-theme font face whose source is /fonts/MS%20Sans%20Serif.ttf. Forcing a sans-serif family does not remove that downloadable face from the browser's font set. Before any diagram renders, we remove only that exact rule from style elements introduced by the trusted plugin loader. This is not a sanitizer for author CSS or arbitrary resources: other rules remain unchanged, and a changed plugin rule still fails closed under CSP and request interception. No font request or recorded violation is excused.

No diagram-type allowlist stands in front of Mermaid's detector. Unknown syntax or unregistered third-party renderers fail explicitly. Remote icon registries, external images, executable callbacks and author configuration remain disabled, regardless of the family requesting them. A new renderer does not gain new browser permissions merely by being registered.

Local, fixed configuration

Only catalogue colors and fixed security settings enter initialization. Source text cannot supply scripts, styles, callbacks, directives or configuration. Stable IDs depend on source and theme, not processing order or wall-clock time. Classic shapes and disabled filters avoid Chromium's rasterization of decorative shadows; the selected palette still controls colors.

A reserved origin is fulfilled once from an in-memory bootstrap document; no DNS request or server is involved. This gives plugins an isolated storage origin instead of the inaccessible storage of about:blank. The bundle is injected as trusted code. CSP denies connections, files, images, fonts, frames and forms; interception aborts every request other than that one bootstrap. Attempted resources or navigation fail the diagram instead of producing an incomplete asset.

Validate the produced vector

Strict Mermaid rendering is not the only boundary. Reject active SVG elements, external references and event handlers. Passive XHTML labels inside foreignObject are permitted because some renderers require them even with htmlLabels disabled; active HTML and all external resources remain forbidden. Local fragment references remain available for markers and glyphs. CSS URLs must also refer to local fragments. These checks run before printing or handing the SVG to the parent.

A context is closed even when parsing, SVG validation or PDF printing fails. The parent deadline still owns a hung context close. The page's font wait concerns installed system fonts only; CSP forbids font downloads. PDF metadata timestamps are normalized without changing byte lengths, preserving cross-reference offsets.

Browser ownership

Puppeteer is imported only in the child. Mermaid's metadata is a static JSON import, embedded by the publication build; no installed package lookup occurs. The build validates the matching browser dependency pins before writing outputs. The browser sandbox remains enabled; there is no fallback to --no-sandbox. The private profile, disabled background services and failed DNS resolution complement page-level request blocking. JavaScript heaps are capped, but this is not a hard operating-system RSS quota.

<<Mermaid browser batch>>=
export async function browserBatch(directory, executable, launch) {

Puppeteer's normal launcher detaches Chromium into a separate process group. Instead, this worker spawns Chromium without detaching, using Puppeteer's fixed default arguments, and connects over a loopback-only debugging endpoint. Thus the controller's process-group kill also covers launch failures and hung closes. The endpoint is never available to diagram page content, whose connections are blocked by CSP and request interception; other local processes under the same user remain outside this isolation model.

<<Mermaid owned browser process>>=
export async function connectOwnedBrowser(puppeteer, options) {
    const args = await puppeteer.defaultArgs({ ...options, args: [...options.args,
        '--remote-debugging-port=0', '--remote-debugging-address=127.0.0.1'] });
    if (!Array.isArray(args) || !args.includes(`--user-data-dir=${options.userDataDir}`)) {
        throw new Error('Puppeteer did not provide the isolated browser arguments');
    }
    const home = path.dirname(options.userDataDir);
    const child = spawn(options.executablePath, args, { detached: false,
        env: { ...process.env, HOME: home, XDG_CONFIG_HOME: path.join(home, 'config'),
            XDG_CACHE_HOME: path.join(home, 'cache'), XDG_DATA_HOME: path.join(home, 'data'),
            CHROMIUM_USER_FLAGS: ' ' }, stdio: ['ignore', 'ignore', 'pipe'] });
    try {
        const endpoint = await browserEndpoint(child);
        return await puppeteer.connect({ browserWSEndpoint: endpoint, protocolTimeout: 15000 });
    } catch (error) { child.kill('SIGKILL'); throw error; }
}

The endpoint announcement has its own deadline and bounded stderr accumulator. Only a loopback WebSocket endpoint is accepted. The stderr listener remains after connection to drain the pipe, but retains no additional browser log data.

<<Mermaid owned browser process>>=+
function browserEndpoint(child) {
    return new Promise((resolve, reject) => {
        let log = '', done = false;
        const finish = (error, endpoint) => {
            if (done) { return; }
            done = true; clearTimeout(timer);
            if (error) { reject(error); } else { resolve(endpoint); }
        };
        const timer = setTimeout(() => finish(new Error(`Chromium launch deadline exceeded: ${log}`)), 15000);
        child.once('error', error => finish(error));
        child.once('exit', code => finish(new Error(`Chromium exited ${code}: ${log}`)));
        child.stderr.on('data', bytes => {
            if (done) { return; }
            log += bytes.toString('utf8');
            if (log.length > 32768) { finish(new Error('Chromium launch log exceeds 32 KiB')); return; }
            const match = /DevTools listening on (ws:\/\/127\.0\.0\.1:\d+\/devtools\/browser\/[\w-]+)/.exec(log);
            if (match) { finish(undefined, match[1]); }
        });
    });
}
