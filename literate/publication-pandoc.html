A controlled Pandoc document bridge

This chapter is authoritative for src/publication-pandoc.ts. It prepares an in-memory Pandoc document from parseProject without running Pandoc, tangling source, loading a template, or writing files. The caller supplies a trusted contribution renderer; ordinary author content never becomes raw output.

Preparation has two phases. First validate the graph and every document's full Markdown token stream, retaining contribution placeholders inside their actual containers. Only after the entire project passes validation may callbacks replace those placeholders. A late unsupported image or missing reference therefore cannot cause an earlier contribution renderer to run.

Diagnostics and graph validation

Positions remain zero-based. Markdown-it does not provide precise positions for inline children, so their diagnostics use the containing inline block's starting line and column zero. Semantic reference diagnostics retain the engine's exact source locations. No fabricated character offsets are inferred from rendered text.

<<publication Pandoc diagnostics>>= 
function report(
    diagnostics: GenerationDiagnostic[], at: PublicationLocation, code: string, message: string
): void {
    diagnostics.push({ ...at, code, message });
}
function tokenLocation(document: ParsedDocument, token?: Token, fallback = 0): PublicationLocation {
    return { path: document.path, line: token?.map?.[0] ?? fallback, column: 0 };
}
function unsupported(diagnostics: GenerationDiagnostic[], at: PublicationLocation, type: string): void {
    const raw = /^(html|raw|tex|latex)(_|$)/.test(type);
    report(diagnostics, at, raw ? 'unsupported-raw-content' : 'unsupported-pandoc-token',
        raw ? `Raw author content is unsupported: ${type}` : `Unsupported Markdown token: ${type}`);
}

Existing parser diagnostics are a hard gate. For otherwise accepted projects, check every reference, even in unused fragments, before inspecting dependency cycles. Reference modifiers are invalid regardless of whether their target exists. Names and boundaries come from publication segments: a literal \<<name>> is never rescanned into a semantic reference here.

<<publication Pandoc graph validation>>= 
interface Dependency { target: string; at: PublicationLocation; }
function validateReferences(project: ParsedProject, diagnostics: GenerationDiagnostic[]): void {
    const families = new Map(project.publication.fragments.map(family => [family.target, family]));
    const edges = new Map<string, Dependency[]>();
    for (const family of families.values()) { edges.set(family.target, []); }
    for (const part of project.publication.contributions) {
        for (const segment of part.segments) {
            if (segment.kind !== 'reference') { continue; }
            if (segment.modifier !== undefined) {
                report(diagnostics, segment.at, 'invalid-reference-modifier',
                    `Invalid definition operator on reference: ${segment.name}`);
            }
            if (segment.resolution.kind === 'missing' || !families.has(segment.resolution.target)) {
                report(diagnostics, segment.at, 'missing-fragment', `Missing fragment: ${segment.name}`);
            } else {
                edges.get(part.fragmentTarget)?.push({ target: segment.resolution.target, at: segment.at });
            }
        }
    }
    validateCycles(edges, families, diagnostics);
}

An iterative depth-first walk uses active and finished sets. It never expands a fragment, so deep or exponentially expanding graphs require only graph-sized storage and traversal. A back edge reports a cycle at the reference that closes it; repeated back edges may produce separate source diagnostics.

<<publication Pandoc graph validation>>=+ 
function validateCycles(
    edges: Map<string, Dependency[]>, families: Map<string, { name: string }>,
    diagnostics: GenerationDiagnostic[]
): void {
    const active = new Set<string>(), finished = new Set<string>();
    for (const target of edges.keys()) {
        if (finished.has(target)) { continue; }
        const stack = [{ target, index: 0 }];
        active.add(target);
        while (stack.length) {
            const frame = stack[stack.length - 1];
            const edge = edges.get(frame.target)![frame.index++];
            if (!edge) {
                active.delete(frame.target); finished.add(frame.target); stack.pop();
            } else if (active.has(edge.target)) {
                report(diagnostics, edge.at, 'fragment-cycle',
                    `Fragment cycle through: ${families.get(edge.target)!.name}`);
            } else if (!finished.has(edge.target)) {
                active.add(edge.target); stack.push({ target: edge.target, index: 0 });
            }
        }
    }
}

Document destinations and links

Each canonical document path gets a separate d- namespace with fixed-width UTF-16 hexadecimal encoding. This is injective and independent of titles, line numbers, and chapter order. Each document, including an empty one, has a Div destination. Headings use a separate h- namespace encoding both document path and allocated slug, separated by a hyphen (which cannot occur in the encoding). Neither author text nor a URL is interpolated into raw TeX.

Generated HTML currently uses plain Markdown-it headings without IDs. The extension installs fence/document renderers on the host preview parser, leaving heading IDs to VS Code; it supplies no slug implementation to reuse. Publication therefore defines its own explicit policy rather than claiming exact preview compatibility. Common lowercase, hyphenated links work where hosts use that convention; duplicate and punctuation behavior can differ.

Slugs use parsed visible text and code spans, including emphasis and link labels, not Markdown delimiters or link URLs. Normalize to NFC, lowercase without locale, remove Unicode punctuation/symbols except hyphens and underscores, then collapse whitespace to hyphens. Normalize the final slug to NFC again before grouping or encoding: lowercasing and punctuation removal can create new composable sequences. Empty results become section. Accents and non-Latin letters remain; fragment matching is case-sensitive and NFC-normalized.

interface DocumentDestination {
    id: string;
    headings: Map<string, string[]>;
    tokens: Map<Token, string>;

type PublicationTargets = Map<string, DocumentDestination>;
function headingSlug(inline?: Token): string {
    const text = (inline?.children ?? []).map(token => {
        if (token.type === 'text' || token.type === 'code_inline') { return token.content; }
        return token.type === 'softbreak' || token.type === 'hardbreak' ? ' ' : '';
    }).join('');
    return text.normalize('NFC').toLowerCase().replace(/[^\p{L}\p{M}\p{N}\s_-]/gu, '')
        .trim().replace(/\s+/gu, '-').normalize('NFC') || 'section';
}

Reserve every natural base slug before allocating duplicate suffixes. A unique base keeps its slug; every member of a duplicate group gets base-1, base-2, etc., skipping reserved or already allocated names. Thus literal Foo-1 cannot steal a duplicate Foo destination. An unnumbered duplicate link is ambiguous and lists usable alternatives. Unlinked duplicates are valid.

<<publication Pandoc heading identities>>=+ 
function headingDestinations(document: ParsedDocument): DocumentDestination {
    const groups = new Map<string, Token[]>();
    document.tokens.forEach((token, index) => {
        if (token.type !== 'heading_open') { return; }
        const slug = headingSlug(document.tokens[index + 1]);
        const group = groups.get(slug) ?? [];
        group.push(token); groups.set(slug, group);
    });
    const destination: DocumentDestination = {
        id: documentTarget(document.path), headings: new Map(), tokens: new Map()
    };
    const reserved = new Set(groups.keys());
    for (const [base, tokens] of groups) {
        allocateHeadings(document.path, base, tokens, reserved, destination);
    }
    return destination;
}

The index scans the full stream before reading any links, so forward links, setext headings and nested headings work without flattening their containers. Identities do not depend on line offsets or chapter order. Unrelated headings do not change IDs; renaming a heading/path or inserting a colliding slug can change them. Duplicate ordinals follow source token order, not arbitrary edit-stable IDs.

<<publication Pandoc heading identities>>=+ 
function allocateHeadings(path: string, base: string, tokens: Token[], reserved: Set<string>,
    destination: DocumentDestination): void {
    const slugs: string[] = [];
    let ordinal = 1;
    for (const token of tokens) {
        let slug = base;
        if (tokens.length > 1) {
            do { slug = base + '-' + ordinal++; } while (reserved.has(slug));
        }
        reserved.add(slug); slugs.push(slug);
        const id = 'h-' + documentTarget(path).slice(2) + '-' + documentTarget(slug).slice(2);
        destination.tokens.set(token, id);
        destination.headings.set(slug, [id]);
    }
    if (tokens.length > 1) { destination.headings.set(base, slugs); }
}

function documentTarget(path: string): string {
    let encoded = 'd-';
    for (let index = 0; index < path.length; index++) {
        encoded += path.charCodeAt(index).toString(16).padStart(4, '0');
    }
    return encoded;
}
function localDocumentPath(href: string, source: string): string | undefined {
    if (!href || /[?#\\\x00-\x20\x7f]/.test(href) || href.startsWith('/')) { return undefined; }
    let decoded: string;
    try { decoded = decodeURIComponent(href); } catch { return undefined; }
    if (/[?#\\\x00-\x1f\x7f]/.test(decoded) || decoded.startsWith('/')) { return undefined; }
    if (!/\.(html|literate)$/.test(decoded)) { return undefined; }
    const parts = source.split('/').slice(0, -1);
    for (const part of decoded.split('/')) {
        if (!part || part === '.') { continue; }
        if (part === '..') { if (!parts.length) { return undefined; } parts.pop(); }
        else { parts.push(part); }
    }
    return parts.join('/').replace(/\.html$/, '.literate');
}

Only HTTP, HTTPS, and mailto schemes are admitted as external links. Relative links must resolve exactly to an included .literate document or its .html alias. Percent-encoded path names and parent-directory navigation are supported without permitting escape above the project root. Split the literal fragment separator before decoding either component exactly once. Queries, empty fragments, malformed escapes, control characters and unsafe paths remain unsupported. Missing included documents, missing headings and ambiguous headings have distinct diagnostics. Link text and titles remain Pandoc data, never TeX commands.

<<publication Pandoc document links>>=+ 
function safeExternalLink(href: string): boolean {
    try {
        if (/[\\\x00-\x20\x7f]/.test(href) || /[\x00-\x1f\x7f]/.test(decodeURIComponent(href))) { return false; }
        const url = new URL(href);
        if (/^https?:\/\//i.test(href)) { return !!url.hostname; }
        return /^mailto:/i.test(href) && url.protocol === 'mailto:' && !!url.pathname;
    } catch { return false; }
}
function linkDestination(
    href: string, document: ParsedDocument, targets: PublicationTargets,
    diagnostics: GenerationDiagnostic[], at: PublicationLocation
): string | undefined {
    if (/^[a-z][a-z0-9+.-]*:/i.test(href)) {
        if (safeExternalLink(href)) { return href; }
    } else {
        const resolved = localLinkDestination(href, document, targets, diagnostics, at);
        if (resolved !== undefined) { return resolved || undefined; }
    }
    report(diagnostics, at, 'unsupported-publication-link',
        `Unsupported link (expected safe HTTP/HTTPS/mailto or an included document/heading without query): ${href}`);
    return undefined;
}

Local resolution returns an empty sentinel for an already diagnosed missing or ambiguous destination, avoiding a second misleading unsupported-link diagnostic. Whole-document links retain their original stable Div destinations.

function localLinkDestination(href: string, document: ParsedDocument, targets: PublicationTargets,
    diagnostics: GenerationDiagnostic[], at: PublicationLocation): string | undefined {
    const hash = href.indexOf('#');
    const path = hash === 0 ? document.path : localDocumentPath(hash < 0 ? href : href.slice(0, hash), document.path);
    let slug: string | undefined;
    if (hash >= 0) {
        try { slug = decodeURIComponent(href.slice(hash + 1)).normalize('NFC'); } catch { return undefined; }
        if (!slug || /[?#\\\x00-\x20\x7f]/.test(slug)) { return undefined; }

Reading inline tokens

The inline reader consumes matching pairs recursively. Ordinary text is split into Pandoc words and spaces; HTML- or TeX-looking text is still ordinary text. Code spans preserve their exact token content. Literal code is not scanned for fragment references. The nesting limit turns excessively nested input into a source diagnostic before JavaScript recursion becomes unsafe.

Closers terminate only the matching container. Unsupported tokens, including images and raw HTML tokens from a caller-provided parser extension, cannot be silently interpreted as strings. Their diagnostics block the whole preparation. Append text nodes iteratively: a flat, very long paragraph must not consume one JavaScript argument per word and exceed the runtime's argument limit.

Reading the complete block stream

Markdown ranges in ParsedDocument.blocks may end inside lists or blockquotes. They are therefore used only to locate accepted contributions, never rendered independently. The block reader walks the complete tokens array with one shared cursor, preserving nesting and authored order across each contribution.

<<publication Pandoc block reader>>= 
interface BlockReader {
    document: ParsedDocument;
    index: number;
    contributions: Map<number, PublicationContribution>;
    targets: PublicationTargets;
    diagnostics: GenerationDiagnostic[];
}
function contributionIndex(
    document: ParsedDocument, parts: Map<string, PublicationContribution>, diagnostics: GenerationDiagnostic[]
): Map<number, PublicationContribution> {
    const result = new Map<number, PublicationContribution>();
    for (const block of document.blocks) {
        if (block.kind !== 'contribution') { continue; }
        const part = parts.get(block.target), token = document.tokens[block.tokenIndex];
        if (!part || part.tokenIndex !== block.tokenIndex || part.definition.path !== document.path
            || token?.type !== 'fence' || result.has(block.tokenIndex)) {
            report(diagnostics, tokenLocation(document, token), 'invalid-publication-snapshot',
                `Invalid contribution binding: ${block.target}`);
        } else { result.set(block.tokenIndex, part); }
    }
    return result;
}

Every block container expects its own closing token. Malformed or excessively nested snapshots produce diagnostics rather than partially published output. Parser-generated snapshots normally satisfy these structural checks already.

<<publication Pandoc block reader>>=+ 
function readBlocks(reader: BlockReader, stop?: string, depth = 0): PendingBlock[] {
    const result: PendingBlock[] = [];
    const tokens = reader.document.tokens;
    if (depth > maximumNesting) {
        report(reader.diagnostics, tokenLocation(reader.document, tokens[reader.index]),
            'publication-nesting-limit', 'Block nesting exceeds 128 levels');
        reader.index = tokens.length;
        return result;
    }
    while (reader.index < tokens.length) {
        const index = reader.index++, token = tokens[index];
        if (stop && token.type === stop) { return result; }
        result.push(...readBlock(reader, token, index, depth));
    }
    if (stop) {
        report(reader.diagnostics, tokenLocation(reader.document, tokens[tokens.length - 1]),
            'invalid-markdown-structure', `Missing ${stop}`);
    }
    return result;
}

Paragraphs inside tight lists become Plain, matching Markdown-it's hidden paragraph markers. Headings retain their explicit level; the future writer may choose chapter-level LaTeX division without changing this document structure. Blockquotes and lists recurse over the same cursor, not isolated token slices.

<<publication Pandoc block reader>>=+ 
function readBlock(reader: BlockReader, token: Token, index: number, depth: number): PendingBlock[] {
    switch (token.type) {
        case 'paragraph_open': return [{ t: token.hidden ? 'Plain' : 'Para', c: readTextBlock(reader, token) }];
        case 'heading_open': return [readHeading(reader, token)];
        case 'hr': return [{ t: 'HorizontalRule' }];
        case 'blockquote_open': return [{ t: 'BlockQuote', c: readBlocks(reader, 'blockquote_close', depth + 1) }];
        case 'bullet_list_open': return [{ t: 'BulletList', c: readList(reader, 'bullet_list_close', depth + 1) }];
        case 'ordered_list_open': return [readOrderedList(reader, token, depth)];
        case 'fence': return readFence(reader, token, index);
        case 'code_block': return [{ t: 'CodeBlock', c: [emptyAttributes(), token.content] }];
        default: unsupported(reader.diagnostics, tokenLocation(reader.document, token), token.type); return [];
    }
}

A text block must contain the inline token followed by its matching closer. The children are already parsed Markdown; feeding token.content to a second parser would introduce a different interpretation of escaping and links.

<<publication Pandoc block reader>>=+ 
function readTextBlock(reader: BlockReader, opening: Token): PandocInline[] {
    const token = reader.document.tokens[reader.index];
    const at = tokenLocation(reader.document, token, opening.map?.[0] ?? 0);
    const stop = opening.type === 'heading_open' ? 'heading_close' : 'paragraph_close';
    if (token?.type !== 'inline') {
        report(reader.diagnostics, at, 'invalid-markdown-structure', `Expected inline after ${opening.type}`);
        return [];
    }
    reader.index++;
    const result = readInlines({ document: reader.document, tokens: token.children ?? [],
        index: 0, at, targets: reader.targets, diagnostics: reader.diagnostics });
    if (reader.document.tokens[reader.index]?.type === stop) { reader.index++; }
    else { report(reader.diagnostics, at, 'invalid-markdown-structure', `Expected ${stop}`); }
    return result;
}
function readHeading(reader: BlockReader, token: Token): PandocLeafBlock {
    const level = /^h[1-6]$/.test(token.tag) ? Number(token.tag.slice(1)) : 0;
    if (!level) {
        report(reader.diagnostics, tokenLocation(reader.document, token), 'invalid-markdown-structure', 'Invalid heading level');
    }
    const id = reader.targets.get(reader.document.path)!.tokens.get(token)!;
    return { t: 'Header', c: [level, [id, [], []], readTextBlock(reader, token)] };
}

Lists consume item boundaries explicitly. An item may hold any supported block, including nested lists and contribution placeholders. Empty item arrays are valid; unknown list children still receive diagnostics.

function readList(reader: BlockReader, stop: string, depth: number): PendingBlock[][] {
    const result: PendingBlock[][] = [], tokens = reader.document.tokens;
    while (reader.index < tokens.length) {
        const token = tokens[reader.index++];
        if (token.type === stop) { return result; }
        if (token.type === 'list_item_open') { result.push(readBlocks(reader, 'list_item_close', depth)); }
        else { unsupported(reader.diagnostics, tokenLocation(reader.document, token), token.type); }
    }
    report(reader.diagnostics, tokenLocation(reader.document, tokens[tokens.length - 1]),
        'invalid-markdown-structure', `Missing ${stop}`);
    return result;
}
function readOrderedList(reader: BlockReader, token: Token, depth: number): PendingBlock {
    const start = Number(token.attrGet('start') ?? '1');
    if (!Number.isSafeInteger(start) || start < 0 || !['.', ')'].includes(token.markup)) {
        report(reader.diagnostics, tokenLocation(reader.document, token), 'invalid-markdown-structure', 'Invalid ordered-list marker');
    }
    const attributes: PandocListAttributes = [start, { t: 'Decimal' }, { t: token.markup === ')' ? 'OneParen' : 'Period' }];
    return { t: 'OrderedList', c: [attributes, readList(reader, 'ordered_list_close', depth + 1)] };
}

All SETTINGS fences are omitted, matching current generation behavior, without activating new settings. Mermaid is explicitly unsupported, including a named contribution whose own language is Mermaid. Other ordinary fences are code data; a tag-looking string there is not a contribution or dependency.

<<publication Pandoc block reader>>=+ 
function readFence(reader: BlockReader, token: Token, index: number): PendingBlock[] {
    if (token.info.trim() === 'SETTINGS') { return []; }
    const part = reader.contributions.get(index);
    const language = part?.language ?? token.info.trim().split(/\s+/)[0];
    if (language.toLowerCase() === 'mermaid') {
        report(reader.diagnostics, tokenLocation(reader.document, token), 'unsupported-mermaid',
            'Mermaid publication is unsupported; no diagram was rendered');
        return [];
    }
    if (part) { return [{ t: 'Contribution', part }]; }
    return [{ t: 'CodeBlock', c: [['', language ? [language] : [], []], token.content] }];
}

Materializing trusted contributions

Only validated pending trees reach this phase. Contributions are replaced in place with zero or more callback blocks, preserving surrounding containers. The callback owns semantic code rendering and may deliberately emit LaTeX RawBlock values. Its output is trusted renderer code, not an author-supplied AST or a custom-template security boundary. Neither the callback nor this bridge should mutate the shared parsed snapshot.

<<publication Pandoc materialization>>= 
function materialize(
    pending: PendingBlock[], render: ContributionRenderer, diagnostics: GenerationDiagnostic[]
): PandocBlock[] {
    const result: PandocBlock[] = [];
    for (const block of pending) {
        if (diagnostics.length) { break; }
        switch (block.t) {
            case 'Contribution':
                            for (const rendered of renderPart(block.part, render, diagnostics)) { result.push(rendered); }
                            break;
            case 'BlockQuote': result.push({ t: 'BlockQuote', c: materialize(block.c, render, diagnostics) }); break;
            case 'BulletList': result.push({ t: 'BulletList', c: block.c.map(item => materialize(item, render, diagnostics)) }); break;
            case 'OrderedList': result.push({ t: 'OrderedList', c: [block.c[0],
                block.c[1].map(item => materialize(item, render, diagnostics))] }); break;
            case 'Div': result.push({ t: 'Div', c: [block.c[0], materialize(block.c[1], render, diagnostics)] }); break;
            default: result.push(block);
        }
    }
    return result;
}

A callback exception is reported at that contribution's declaration. No public document is returned, and later callbacks are not invoked. Earlier callbacks cannot be undone, so callers should keep rendering free of external side effects. The array check catches a common untyped-caller mistake, but is not presented as validation or sanitization of the trusted renderer's complete output tree.

<<publication Pandoc materialization>>=+ 
function renderPart(
    part: PublicationContribution, render: ContributionRenderer, diagnostics: GenerationDiagnostic[]
): PandocBlock[] {
    try {
        const blocks = render(part);
        if (!Array.isArray(blocks)) { throw new Error('Contribution renderer must return a block array'); }
        return blocks;
    } catch (error) {
        report(diagnostics, part.definition, 'contribution-render-failed',
            `Contribution renderer failed: ${error instanceof Error ? error.message : String(error)}`);
        return [];
    }
}

Preparing the document

The public API preserves document order and returns either a complete document with no diagnostics or diagnostics without a document. Existing parse diagnostics are copied, not mutated. Graph validation never calls the contribution renderer; token validation still runs across all documents when graph errors are found, so callers receive both graph and content diagnostics in deterministic order.

<<publication Pandoc preparation>>= 
export function preparePandoc(
    project: ParsedProject, renderContribution: (part: PublicationContribution) => PandocBlock[]
): PandocPreparationResult {
    const diagnostics = project.diagnostics.map(diagnostic => ({ ...diagnostic }));
    if (diagnostics.length) { return { diagnostics }; }
    validateReferences(project, diagnostics);
    const targets = new Map(project.documents.map(document => [document.path, headingDestinations(document)]));
    const parts = new Map(project.publication.contributions.map(part => [part.target, part]));
    const pending: PendingBlock[] = project.documents.map(document => {
        const contributions = contributionIndex(document, parts, diagnostics);
        const body = readBlocks({ document, index: 0, contributions, targets, diagnostics });
        return { t: 'Div', c: [[targets.get(document.path)!.id, [], []], body] };
    });
    if (diagnostics.length) { return { diagnostics }; }
    const blocks = materialize(pending, renderContribution, diagnostics);
    if (diagnostics.length) { return { diagnostics }; }

    return { document: { 'pandoc-api-version': [1, 23, 1], meta: {}, blocks }, diagnostics };
}

The intended cases are deliberately narrow: nested prose and contributions, ordinary code, stable document-to-document links, and exact semantic callback inputs. Missing references, invalid modifiers, cycles, unsupported tokens, Mermaid, and unresolved heading links block callbacks. HTML/TeX-looking ordinary text remains data. Empty projects produce an empty Pandoc document. Font selection, syntax highlighting, LaTeX assembly, process execution and export commands live in their own adapters; images and tables remain unsupported.
